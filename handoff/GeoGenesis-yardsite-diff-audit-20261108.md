## 〇、先给结论（重要，且与我此前的说法相反）

**1. 参考项目的算法在我们的数据上并不好看。**

实测（`diff_audit.py`，真实生产地形 65536 格）：

| 光照方案 | gain | 光照 p5 | p50 | p95 | 饱和率 |
|---|---:|---:|---:|---:|---:|
| 参考项目固定 0.55 | 0.55 | **0.987** | **0.998** | 1.000 | 0.0% |
| 我们的自适应（P99.5→0.9） | 11.78 | 0.717 | 0.967 | 1.000 | 2.0% |

⇒ 参考项目的 `gain=0.55` 在我们数据上 **95% 的格子明暗差不到 1.3%**，
出图就是一片平滑的绿（`build/cmp-ref.png` 左半）。这不是"我们做得差"，
而是**同一个常数在两套不同的坡度量级上不可比**：

- 参考项目 `slope = ΔY / (2·step·HEIGHT_STRIDE) = ΔY / 62.4`
  （`SiteMapSampler.java:553-555`）→ 量级 0.1~1.0
- 我们的 `slope = Δ(柱高比例)` → 实测 p50 = **0.0028**（差 **约 30~300 倍**）

**2. 所以"像参考项目"这个目标本身需要重新定义。**
参考项目好看的前提是它的两件事我们都没有：
- 它的数据是 `Heightmap.Types.WORLD_SURFACE_WG`（`SurfaceProbe.java:56`）——
  真实方块地表，含水面、雪层、树叶、结构；我们用的是纯噪声场 `sampleCellCoarse`。
- 它有**两层视图**（大沙盘 ±2000 格 / 区块精读 16 格一格），靠切换提供"看清细节"；
  我们是单层连续缩放。

**3. LOD 换算本身没错，"看不到变化"是构图问题。**
实测 `windowFor` 从 zoom 2.0→31.2 单调 4000→256（14 步每步都变），
但柱数恒定 128、`span` 又按最高点自动重标定
⇒ 窗口缩小 20% 时画面只是"整体缩小一点+柱高重新拉满"，
**构图几乎一样**，主观上就是"没变化"。

## 二、真实差异（按影响从大到小）

### D1 ★★★ 数据源不同（最根本）

| | 参考项目 | 我们 |
|---|---|---|
| 高度来源 | `Heightmap.Types.WORLD_SURFACE_WG`（`SurfaceProbe.java:56`） | `sampleCellCoarse` = 纯噪声求值 |
| 含义 | **方块地表**：含水面、雪层、树叶、结构 | 噪声场，无方块细节 |
| 水面 | 水格直接记 `seaLevel`（`SiteMapSampler:485`） | `e<0` 判水，另叠加粗层水位 |
| 雪 | 由方块决定 | `Cell.isSnow`（雪线逻辑） |

**影响**：参考项目的地形"有东西"（海岸线锯齿、雪线、水面纹理），
我们的地形是光滑噪声场 ⇒ 即使柱高/颜色全对，观感也不同。

**能否弥补**：不能完全。要等价必须走 `sampleCell`（完整管线），
实测 **3.6~10.9 秒/region**（`[HYDRO-MODEL] region solved in 10862 ms`），沙盘不可用。

### D2 ★★★ 坡度量级差 30~300 倍（同一 gain 不可比）

- 参考：`slopeX = (right-left)/(2*step*HEIGHT_STRIDE)`，`step≈15.6` ⇒ 分母 **62.4**
- 我们：`slope = Δ(柱高比例)`，实测 p50 = **0.0028**

⇒ 直接把 0.55 抄过来 = 几乎全亮（实测 p50=0.998）。
我们改用自适应（P99.5→0.9，实测 gain=11.78）才有层次。

**这是"看起来不像"的第二大来源**（参考项目在我们数据上反而更平）。

### D3 ★★ LOD 的呈现方式不同（"滚轮没变化"的真因）

| | 参考项目 | 我们 |
|---|---|---|
| 视图层数 | **2 层**：大沙盘（±2000 格）+ 区块精读（16 格/格） | **1 层连续** |
| 换精度方式 | **切层**（`enterDetail`，带 620ms 过渡动画） | 滚轮连续改窗口 |
| 默认缩放 | 大沙盘 2.0、精读另算（`defaultZoom()`） | 2.0 起连续 |
| 缩放范围 | 0.6~8.0 | 0.6~31.2 |
| 构图变化 | 切层时**镜头推近 + 旧图淡出下沉**（`TRANSITION_MS=620`） | 窗口缩小，柱子数不变 |

**为什么我们"看不到精度变化"**：
滚轮 1.12 倍/步 ⇒ 窗口只缩 11%，而 `span` 按最高点自动重标定、
柱数恒定 ⇒ 画面就是"整体小一圈 + 柱高拉满"，**构图几乎相同**。
参考项目靠切层时镜头推近 4 倍（±2000→±500）才有"进来了"的感觉。

### D4 ★★ 缺 hover / 选中 / 高亮（交互反馈）

| 项 | 参考项目（行号） | 我们 |
|---|---|---|
| hover 顶面提亮 | 503-507 行，`0x4C` alpha 白 | 有 `pick()` 但**渲染没用** |
| 调色群系高亮 | 476-484 行，`colHighlight` 顶面压 `0x44` 白 | ❌ 无 |
| 选中 footpring + pin | 508-515 行，金框 + 金色针 | ❌ 无（我们不选点） |
| 蓝图叠加 | 499-501 行 | ❌ 不采纳 |

### D5 ★ 同色群系的 jitter 覆盖面

- 参考：`0x3D6B32` 一个绿覆盖 **7 个群系**（forest/taiga/birch/dark...），
  靠 `jitter()`（±6%，`BiomePalette:157-161`）区分边界
- 我们：10 个 Whittaker 类型，`TAIGA/TEMPERATE_FOREST/SEASONAL_FOREST` 同为 `0x3D6B32`，
  `TEMPERATE_RAINFOREST/TROPICAL_RAINFOREST` 同为 `0x2E7A35`
  ⇒ **同色相邻时边界完全消失**

### D6 ★ 调色板色值细节

参考项目 `baseColor` 有 12 类硬编码 + HSV 兜底（`BiomePalette:109-154`）。
我们的 `SandboxPalette` 只有 10 项，且 `TUNDRA` 用 `0xB8C8C0`（参考用 `0xE7F0F5` 系）。

### D7 （已解决，记录）边缘渐隐

参考项目大沙盘 `edgeFade()` **恒 1.0**（`SiteMapSampler:344-346`），
只有区块精读才真渐隐。我们全屏地图需要渐隐 ⇒ 已实现（3 柱 smoothstep）。
**这是有意偏离，不是缺陷。**

## 四、待用户裁定的选择点

**Q1. 要不要做"两层视图"？**
参考项目的"看清细节"靠切层 + 镜头推近。我们是连续缩放，
滚轮只缩 11%/步，主观上"没变化"。
- 方案 A：滚轮步长加大（如 1.4 倍/步）→ 变化明显，但精细调整变难
- 方案 B：加入参考项目式切层（大沙盘 ↔ 精读）
- 方案 C：保持连续，但**加减速**（近处慢、远处快）

**Q2. 数据源要不要升级？**
要"像参考项目"就必须有方块级地表（水面/雪/树），
但那需要 `sampleCell`（3.6~10.9 秒/region）。
- 方案 A：只在小窗口（≤500 格）时对**可见的少数 chunk**走完整管线
  （约 30×30 chunk，需实测总耗时）
- 方案 B：维持噪声场，靠配色/光照/水面把观感做足

**Q3. 同色群系边界（D5）要不要补 jitter？**
补了能立刻改善"一大片同色"的观感，代价是同色群系看起来有细微明暗差。

**Q4. hover 提亮（D4）要不要接？**
`pick()` 已经能算命中柱，只差渲染时用它提亮顶面。
