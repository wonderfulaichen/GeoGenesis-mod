## 一、本轮我犯了什么错（按严重度）

### 1.1 在缺规格时靠猜，每次猜错就整块重写

`SandboxLod` 被我**重写 7 次**。每次都是因为需求理解错：

| 版本 | 我理解的 LOD | 实际结果 | 用户判定 |
|---|---|---|---|
| v1 | 离散 4 档 `round(log2(zoom/2))` | 滚轮 13 格停在同档 | 看不到变化 |
| v2 | 网格固定 256、窗口随缩放 | 精度不随缩放变 | 放大没变化 |
| v3 | 网格按视口像素（450²） | 柱数固定、构图不变 | 假 LOD |
| v4 | 聚合系数分档 8/4/2/1 | 柱数仍固定 | 假 LOD |
| v5 | 四叉树：柱数 ×4 | 窗口恒 2400（柱数×2 与每柱÷2 抵消） | 视野不动 |
| v6 | scale 不乘 zoom | 有推进感但柱数不变 | — |
| v7 | 窗口连续 + 档位跳 | 同心弧纹理（柱子太细） | 越改越多 bug |

**根本原因**：我每次只拿到一句反馈，就当作完整规格去重写。
应该先把「窗口怎么变 / 柱数怎么变 / 默认档在哪」三个问题一次性问清。

### 1.2 改了参数不做端到端验证

`scale` / `span` / `perColumn` / `GRID` 这些量互相耦合：

```
scale   = areaSize × 0.46 × zoom      （屏幕缩放）
window  = 网格 × 每格方块              （世界范围）
柱屏幕px = areaSize / 柱数
```

**只要其中两个独立变化，第三个就会被挤坏。**
我改了 6 次都只调其中一两个，没有同时约束三者，导致：
- `scale` 乘 zoom + window 除 zoom ⇒ 抵消 ⇒ 构图不变
- 柱数 ×2 + 每柱方块 ÷2 ⇒ 窗口恒定 ⇒ 视野不动
- 柱数过多（128/820px = 6.4px）⇒ 柱顶+侧墙叠成同心弧

### 1.3 修 A 引入 B

| 修复 | 引入的新问题 |
|---|---|
| 修柱缝（`modelEdge` 用 `fine` 作分母） | 与 `snapTop` 的像素吸附叠加后，顶面与墙错位 |
| 修斜向纹理（`snapTop`） | 只用于判断、绘制仍用原值 ⇒ 判过了照样画亚像素墙 |
| 修"功能都没有"（HUD 调用） | 与 `ConfigScreen.renderStatusHud` 重复绘制 ⇒ UI 重叠 |
| 加四叉树 LOD | 窗口恒等式 ⇒ 视野不动 |

### 1.4 沙盘没有可用的验收手段

平面视图有 `runDefaultOutputFingerprintProbe`（逐位对拍），
沙盘只有我自己写的离线出图脚本 —— **脚本和渲染器都是我写的，可能一起错**。
所以“探针 PASS”对沙盘几乎没有保证力。

## 三、待确认的规格（必须一次定死）

这三个量**只能有两个独立**，第三个是结果。请指定哪两个：

### 选项 A：以「窗口」和「柱数」为独立量
```
窗口  = 2400 / 2^k          （用户滚轮控制 k）
柱数  = 32 × 2^m            （用户滚轮同时控制 m）
每柱方块 = 窗口 / 柱数       （结果）
```
- 优点：两者都能变，视觉上"既推进又变细"
- 风险：若 k 与 m 同步，就会重演"抵消"问题

### 选项 B：以「窗口」和「每柱方块」为独立量
```
窗口     = 2400 / 2^k       （滚轮）
每柱方块 = 75 / 2^j         （比窗口变化快/慢）
柱数     = 窗口 / 每柱方块   （结果，自动 ×2）
```
- 优点：柱数自动跟随，不会抵消
- 需要你定：j 与 k 的比例（1:1 会抵消，2:1 才不抵消）

### 选项 C：固定柱数，只变窗口（最简单）
```
柱数 = 128 固定
窗口 = 2400 / 2^k
每柱方块 = 窗口/128
```
- 优点：绝不会出弧纹（柱数恒定）
- 缺点：推近时柱子会变大，不是"变多"

## 五、同心弧纹理的确切原因（已定位）

`128 柱 / 820px = 6.4px 每柱`。每根柱的顶面 + 1px 侧墙边界，
在 6.4px 宽度下变成"结构噪声"，叠成同心弧。

**参考项目为什么没有**：它 128 柱覆盖 **4000 格**（每柱 31 格方块），
柱高差相对柱宽很小；而我们 128 柱只覆盖 **608 格**（每柱 4.75 格），
高差相对柱宽大得多，每个台阶都变成可见的墙。

**结论**：柱子的屏幕尺寸有一个**可见下限**（实测约 12px）。
低于它，方块结构必然糊成纹理。

**修法**：柱数上限 = `视口像素 / 12`。超出时不再增柱，改由"每柱方块减少"提升精度。
