## 4. 三个缺陷与共同根因

### 缺陷 1：放射状伪影（④海岸带最明显）

`RidgeValleyErosion.evaluateCell` 里的 `landMask`：

```java
float coastDist = Math.abs(h - seaE);
float landMask = Math.min(1f, coastDist / 0.15f);   // ← 海平面附近硬性渐隐
```

这是为"海岸不造假山脊"加的，但它在 `|h−seaE| < 0.15` 范围内制造了**梯度突变**，
而骨架的条纹方向依赖 `norm(gx,gz)` ⇒ 方向在海岸带内剧烈变化 ⇒ 放射星。

这正是 Rune 博客 §Preserving peaks 说的问题："where the steepness is zero,
the direction of the gradient changes abruptly … creates chaotic stripe patterns"。

### 缺陷 2：山地被抹平（⑥⑦）

原始山脊清晰，加骨架后变糊。**这与预期相反**。

原因推测（未验证）：骨架 delta 是从**预平滑后的场**算出来的，携带的是低频特征；
把它加到**未平滑的原始地形**上，等于给锐利地形叠了一层低频扰动 ⇒ 视觉上"糊"。

### 缺陷 3：幅度失控（全局 max 67 格 vs 生产 ±5 块）

生产里骨架吃的是 `terrainEQuick` 的**粗分辨率场**（`CellGenerator` 里有 `skelSpacing` 抽稀 +
三区平滑），全程在粗尺度上；我这里是"平滑全分辨率场 → 骨架 → 叠加到全分辨率原图"，
**两个尺度不匹配**。

### 共同根因

**接入点错了。** 生产里骨架是流水线的一环：

```
粗地形（terrainEQuick，平滑） → 骨架 → 填块 → 液滴 → 最终地形
```

它拿到的是**不含海岸剖面的粗地形**；我喂的是 `compose-coastal` 的最终 e
（已含 `cliffFactor` / `landMask` / 水下细节带 / 海岸三段剖面）。
这些后加的细节让梯度与 `combiMask` 全部失真。

## 5. 结论与决定

**在沙箱里用"点式地形 + 后置骨架"永远无法复现生产的骨架行为。**
因为骨架是**地形生成流水线的一环**，不是后处理滤镜。

## 6. 留给后续的三条线索

等正式接入时，以下三点值得重点看：

1. **海岸带的放射星**：`landMask` 在 `|h−seaE|<0.15` 的渐隐是否够平滑。
   生产里骨架不吃海岸剖面，理论上不会有这个问题——但**需要实测确认**。
2. **山脊是否被抹平**：生产里骨架在液滴**之前**，液滴会在骨架上再刻细节，
   理论上不会糊。沙箱后置叠加看不到这个顺序效应。
3. **delta 幅度**：生产里骨架 delta 的实测范围（跑一次 `runClient` 看 `[PERF]` 日志，
   或在 `CellGenerator` 里加临时打印）。
