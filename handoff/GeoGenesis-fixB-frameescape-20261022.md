# 修复 B（边框横向长直）— 取证与结论（2026-10-22）

## 1. 一句话结论

**找到精确几何来源，也找到窗口裁剪机制，但修不动** —— 因为窗外那条路
本身终止于一个真实洼地。**默认关闭，如实标记为未修。**

## 2. 精确几何来源（此前只有推测，现在有数）

`z≈608` 那条 403 块水平线，**不是多条折线首尾相接**，而是**单条折线自己横走**：

| 折线 | 落在 |z-608|≤3 的点数 | x 跨度 |
|---|---|---|
| **poly#0** | **412** | **294.5 块** |
| poly#4 | 43 | 66.2 块 |
| poly#8 / #13 / #22 / #24 / #26 / #39 / #53 | 4~5 | 0.1~3.3 块 |

格路径层同样确认：`reach#0` **独占该行 128 个节点、横跨 292 块**，其余 reach 仅单点。

⇒ 缺陷集中在一个上游链上，范围明确。

## 3. 窗口裁剪机制（决定性证据）

`reach#0` 沿 `x=-458` 南下，到 `z=608`（= `oz + (n-1)*STEP`，**窗口最后一行**）后：

```
[274] (-458,606)
[275] (-458,608)   ← 到达边框
[276] (-456,608)   ← 改为横走
[277] (-454,608)
...                 z 恒为 608
[327] (-354,608)
```

同一段**窗外地形确实更低**：

| x | 窗内 bed | 窗外 (z+2) bed |
|---|---|---|
| -456 | 64.315 | **64.296** |
| -442 | 64.273 | **64.254** |
| -386 | 64.131 | **64.115** |

⇒ 水本该继续南下。`vectorTraceNext` 的 8 邻越界检查跳过了窗外候选，
只能在**行内**找更低的格 ⇒ 横向长直。**这是窗口裁剪伪影。**

## 4. 为什么修不动（关键）

实现了 `FRAME_ESCAPE`：站在边框格时优先改走 `continueOutside`（窗外真实地形下降）。
但实测走不通：

```
start=(-458,608) h=64.321 seaLevel=63.000
走了 92 步后停在 (-366,653) h=63.834  reason=NO_DESCENT
```

从 `(-366,653)` 再走：**0 步，立刻 NO_DESCENT**（8 邻全更高）。

⇒ 窗外那条路**终止于一个真实洼地**（h=63.834，高于海平面 63.0，但无处可走）。
`continueOutside` 要求必须到海/湖才返回非 null，故如实返回 `null`
⇒ 开关打开与否**产出一致**（`FrameEscapeProbe` 仍测到 127 步横走）。

## 5. 真正的问题结构（修正我此前的说法）

我此前说"z=608 是缺陷 B（边框 NEARBY 假汇流）"。**这个描述不准确**。实测结构是：

| 层 | 现象 | 性质 |
|---|---|---|
| 1 | 链到边框后不再南下，改为行内横走 | **窗口裁剪伪影**（窗外有更低但不可见） |
| 2 | 窗外续流 92 步后撞上 8 邻全更高的洼地 | **洼地缺出口** |

两者叠加。**只修 (1) 不够** —— 水仍会停在洼地。

这与 `DeadEndCauseProbe` 的结论完全一致：owner(-1,0) 的 3 个 DEAD_END
**全部是真实局部极小**（18/20 跨 owner 合计）。

## 6. 因此下一步的正确方向

**必须先有洼地/盆出口能力**（合法成湖，或找到鞍部溢流继续下泄），
而不是继续在追踪层打补丁。`spillCell` 现有 `MAX_SPILL_RISE=12` 上限，
需量化这 92 步路径终点、以及那 18 个真洼地的鞍部抬升分布，
判断是阈值过严还是真的无出口。
