用户已定稿，不能再当作选型题：

- 新世界是原大陆机制向海陆全世界的扩展，不是三套生成器的外部拼装。
- **分布只决定类型与空间位置；类型决定自身高度和形态。** `c` 只参与类型选择，不作为最终高度或水边阈值。
- 内部类包括陆地内部类型和海洋内部类型。普通过渡类包括陆陆、海陆、海海，一般不自造形态，由参与的内部类型决定。
- 海岸是有地貌加工的**特殊过渡类型**，不是独立占区的第三种内部类。
- 地形类型对应现实地形地貌定义；不把节点算法名、后验高度标签当成地貌类型。
- 共用已研制的**节点形态过渡**，不是对多个成品高度做最终 lerp，也不是各建一套“陆海/海海专用过渡”。

冻结当前距离修复B图：`SHA256 5af5df1fd9d78c45d91398deda1a3773bc49635a8573515a63d97daba433befe`，水面29.7460618779%。它是本轮对照资产，不表示海岸形态或完整架构已经验收。见 [verification.json](../../handoff/attachments/distance-fix-20261101/verification.json)。

**保持数值不变**：18项陆地目录与45槽、5项海洋配方、所有噪声种子/偏移/频率/振幅/偏置、权重、海平面与HeightCurve、既有240/±120块普通形态过渡、80～116块特殊海岸加工带、8块距离网格、海岸剖面分段位置与高度旋钮、覆盖层既有阈值。不能为消线偷偷加宽、加噪声或调高低。

“参数冻结”不等于“完整新图逐位不变”：取消硬选、加入真实形态过渡会改变边界与海陆占比；必须报告变化，不通过反向调参恢复百分比。普通过渡的240块与海岸加工的80～116块是两个职责不同的范围，不互相替换。

### 2.3 贴岸黑崖线：有配方自身陡折，不宜一概认定为边界切换

[CoastRecipeCatalog.java:196-204](../../forge-1.20.1-47.4.10-mdk/src/diagnostics/java/com/geogenesis/worldgen/terrain/candidate/CoastRecipeCatalog.java#L196-L204) 的SEA_CLIFF剖面在t=0.35进入 `0.22+0.66*u^0.45`。`u^0.45` 的右导数在u=0趋于无穷，t=0.55又换成低斜率直线；剖面高度连续，但不满足一阶平滑。

另有源码确定的水边端点不一致：[profileShape:197-199](../../forge-1.20.1-47.4.10-mdk/src/diagnostics/java/com/geogenesis/worldgen/terrain/candidate/CoastRecipeCatalog.java#L197-L199) 在t=0返回0.07；[evHeight:235-244](../../forge-1.20.1-47.4.10-mdk/src/diagnostics/java/com/geogenesis/worldgen/terrain/candidate/CoastRecipeCatalog.java#L235-L244) 的陆侧极限为 `shore+(anchor-shore)*0.07`，而 [UnifiedWorld:387-390](../../forge-1.20.1-47.4.10-mdk/src/diagnostics/java/com/geogenesis/worldgen/terrain/candidate/UnifiedWorld.java#L387-L390) 水下极限为 `shore`。此前“严格连续”的注释不成立。这个缺陷存在，但本轮未做截图逐段水边极限定位，不能把全部红线归给它。

目标只有一条：

```text
固定世界区域/站点身份
  → 分布层为站点选内部RecipeId（陆地或海洋；c只在这里使用）
  → 同一几何层给出所有有效区域的连续权重
  → 同RecipeId+seed先归并并归一（只ease一次）
  → 同一节点形态引擎：内部信号/非线性加工/amp/bias/合法范围

```

三类普通过渡是参与者的语义标签，不是三个实现分支；不枚举手写每一对成品过渡配方，不仅挑最近两类型。多域交汇允许所有紧支撑有效候选；第三类权重归零时严格退回对应双族路径。

## 4. 分阶段实施

### P0 固化与反向验证

- 固化本方案§1的B raw、seed、JVM属性（出图仅`file.encoding=UTF-8`）、参数快照、源码SHA、类型身份与旧陆地门禁。
- 为§2四个问题建立独立样点测线：海型切换、岸型切换、同岸型剖面折点、水边极限；先证明旧实现会FAIL，再作为新链回归。
- 历史7臂raw与旧陆地18项目录保留，不用当前不完整新世界取代已认可旧基准。

### P1 抽出唯一节点形态内核，先不接海洋

- 从`RecipeJunctionMorph`泛化目录访问与算子角色，不复制一个OceanMorphEngine。保留已有类的薄适配入口，实际指向同一求值实现。
- 不改18项目录本身的编号、种子、raw分解、原始selector、复合项语义和float运算顺序。固定层次仍是域/源信号→非线性算子→amp/bias→配方约束。
- 现有台地、劣地、山地角色从目录读取，不再让全世界逻辑假定固定15/16/17。海洋不贡献这些角色时不得凭空激活它们。
- 先跑陆地18端点、十条双族、三向退边、重排不变、tile缓存回归。纯陆权重路径必须保持现有逐位结果或原测试明确的既定数值容差；不笼统承诺“所有reference都逐位”。未通过不进入P2。

### P2 海洋接真实节点，不伪装成`raw=成品高度`

- 五配方保持原始公式与seed，将真实源节点/门控/高斯鼓包/振幅/偏置拆成节点描述，复用同一内核。负幅度（CANYON）、负bias为一等合法值。
- 统一输出单位为**e**。陆地保留`GROUND_E + E_SPAN*h`语义，海洋原值已是e；适配放在描述器，不给海洋额外套陆地GROUND_E/E_SPAN。
- **clamp顺序必须保端点**：陆地复合的`max(h,0)`是加GROUND_E之前的配方内部算子；陆地外层`max(e,0)`与海洋范围约束分开表达。不能把三种clamp粗暴平均后截掉所有负e。
- 不用`raw=(height-bias)/amp`倒算伪拆分；不插值seed/倍频整数；海洋形态幅度不因重构改变。
- onehot每个配方对旧公式对拍；任意纯海双族不得无故出陆；海陆权重扫全区间须能跨0，且负幅度穿零不得除零或翻成正向山脊。若中间形态扭曲，报告节点对应问题，不调配方参数掩盖。

### P3 分布层与统一权重，替掉当前点级硬切

- 复用现有`RegionPartition`几何、world tile、候选完整性、`progress/normalize/mergeToEntries`，不新增另一套地形空间。
- `c`、现有类型概率/权重在**稳定世界站点身份**处用于选择陆/海RecipeId；使用站点独立hash/seed，不推进陆地既有游标、不在每个查询点重选类型。
- 同一站点在不同tile/窗口/查询顺序下必须获得同一RecipeId。既有陆地槽→18条目映射保持；海洋独立槽权重原值保持，不把`c`枚举顺序当深度曲线。
- 各站点的空间权重统一交给P1内核；陆陆、海海、海陆走相同求值入口。删除新链对`isSea?成品海高:成品陆高`及`UnifiedTerrainCatalog.merge`的依赖。
- **预期变化提前说明**：把点级噪声硬阈值分布改成既有区域机制的稳定站点选型，区域布局、海陆面积可能变化；这是接线/拓扑变化，不是调参。P3必须先给类型布局与原图同窗口A/B，不把它说成“只有高度变了”。
- 性能先实测：复用已有缓存/几何索引；记录有效候选数、几何建场、采样/区块成本。新增海洋参与者会增加边界求值，不能预先承诺零开销，也不以优化名义削减形态。

### P4 海岸：统一引擎内的特殊过渡加工

- 海岸仅在**有正权重陆型与海型相邻**的过渡上下文中启用，且受已有80～116块加工范围约束。它没有独立内部区域票槽。
- 上下文来自同一内部类型/权重场：参与陆型与海型、有效权重、未经海岸加工的连续e、世界边界关系。实际水边仍由最终e穿0决定。不能再用旧硬选baseE的岸线覆盖新引擎。
- 海岸方向由相邻海陆关系与一次性的基础场距离计算提供，**不使用自有噪声梯度决定朝向**。修好的EDT只作几何支持，距离不作地形噪声坐标。
- 岸型间也以连续参数权重参与特殊加工，不再硬切整份沙滩/崖岸成品高度。过渡外加工强度及其一阶变化归零，保留内部端点；海陆多向交汇统一求值，窄地峡两侧岸带不能逐边覆写、依赖顺序。
- 原剖面分段位置、幅度、沙滩封顶及加工带数值先冻结；先显示只修“类型过渡”能解决哪些线。
- **独立子项，不偷改**：§2.3的`u^0.45`奇异导数与崖岸t=0端点错误不会因共享引擎自动消失。先用端点约束/剖面分析确定保持现有控制点数值的连续实现，单列“特殊加工连续性修正”局部臂；不能混进普通引擎重构结果，也不能改0.45等参数冒充接线修复。若无不改参数的合理节点表示，停在门禁FAIL并回报，不能擅自调参。
- `FullMorphLand`旧覆盖层先作为原陆地语义保留。进入海陆混合时贡献需随相应陆地参与量连续归零，不能把旧台地覆盖铺入纯海区；不能按旧MOUNTAINS标签换成另一配方。纯陆对拍单列。

### P5 整图接线、无限世界边界与交付

- `UnifiedWorld`只做同一引擎的调度/导出，不保留“陆地成品→海洋成品→d覆盖”第二高度管线。旧入口只作回归对照，不作为新链运行时依赖。
- 当前`FullMorphLand`只允许固定Gallery seed（[126-133](../../forge-1.20.1-47.4.10-mdk/src/diagnostics/java/com/geogenesis/worldgen/terrain/candidate/FullMorphLand.java#L126-L133)），当前EDT依赖有限整图窗口。这两项必须列明，不把复用现有代码等同于已经支持无限世界。
- 使用固定世界tile与足够halo覆盖普通±120和特殊最大116块支持范围，不依赖本次图片边界或全图分位统计。输出同一点在不同窗口、tile顺序、缓存淘汰、负坐标下相同。找不到异类时“无海岸影响”，不能窗口边缘伪造岸。
- 优先复用`LocalBoundaryGeometry`的world折线/候选查询；其反warp与非单射限制仍需失败检测和不同精度对拍，不能仅靠一个窗口PASS做严格证明。非标准seed用真实构建链验证，不绕过Gallery限制假装生效。
- 完整新臂用真实统一入口导出e和Y、内部类型及权重、过渡类型/加工强度、距离/范围。渲染仅展示该输出，不在Python合成新的高度来冒充效果。

## 6. 出图、性能与停止点

每阶段先门禁后出图，独立输出目录，保留距离修复基准不覆盖：
