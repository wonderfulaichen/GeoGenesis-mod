## 玩家加入世界崩溃修复（biome palette null Holder NPE）

- **现象**：世界可生成（DIAG SUCCESS，生成到 97%），但玩家加入时崩溃 `Couldn't place player in world` → `NullPointerException: Holder.value() 为 null` @ `LinearPalette.getSerializedSize` → `Registry$1.getId`（即 `Registry.asHolderIdMap()` 的 `getId(Holder)`）。
- **根因**：`GeoGenesisBiomeSource.getNoiseBiome` 此前返回 `null`（`possibleBiomes` 为空集合）。`ChunkGenerator.createBiomes` → `fillBiomesFromNoise(biomeSource)` → `getNoiseBiome` 把 null `Holder<Biome>` 写进区块 biome palette，序列化时 `registry.getId(null)` 空指针。注意崩溃栈里的 `Registry$1` 是 `asHolderIdMap()` 的匿名 `IdMap<Holder<Biome>>`，说明崩溃发生在 **biome palette**（不是 block palette）。
- **修复**：
  1. `getNoiseBiome` 改为：按需初始化共享地形引擎 → `terrain.sampleCell(QuartPos.toBlock(x), QuartPos.toBlock(z))` → `BiomeClassifier.pickKey(cell)` → `ForgeRegistries.BIOMES.getHolder(key)`；地形未就绪时回退到 plains（非 null）。
  2. `collectPossibleBiomes` 改为枚举 `BiomeClassifier` 实际可能产出的全部 `ResourceKey<Biome>`（经 `ForgeRegistries.BIOMES.getHolder` 解析），`getBiomesWithin` 返回 `possibleBiomes()`。
  3. `GeoGenesisGenerator` 抽取静态 `getOrInitTerrain()`（共享引擎，`worldSeed` 播种）；`setWorldSeed` 重置 `sharedTerrain=null` 以便换种子重建。背景：ChunkStatus.BIOMES 在 fillFromNoise 之前采样 biome，故引擎必须能独立于 fillFromNoise 初始化。
- **关键 Forge 陷阱（新）**：本 Forge 1.20.1 MDK 的 `BuiltInRegistries` **没有 `BIOME` 字段**（群系是动态/Forge 注册表，已从 BuiltInRegistries 移除）。按 `ResourceKey<Biome>` 解析 `Holder<Biome>` 必须用 `net.minecraftforge.registries.ForgeRegistries.BIOMES.getHolder(key)`。同理 `BLOCK` 等 vanilla 静态注册表在 Forge 下多被标 `@Deprecated` 并指向 `ForgeRegistries`。

## 纠正：ForgeRegistries.BIOMES 同步时机 → ServerLifecycleHooks 方案

- 初版修复用 `ForgeRegistries.BIOMES.getHolder(key)` 又崩溃（"minecraft:plains not registered"@ createLevels → createBiomes）。
- **根因**：`ForgeRegistries.BIOMES` 是 Forge 的静态注册表包装，在世界生成初期（`createLevels`→`createBiomes`）尚未从当前世界的 dynamic 注册表同步数据，故 `getHolder(plains)` 返回 empty → 抛 `IllegalStateException`。
- **最终方案**：优先使用 `ServerLifecycleHooks.getCurrentServer().registryAccess().registryOrThrow(Registries.BIOME).getHolder(key)`。Forge 在 `MinecraftServer` 构造期即 `setCurrentServer(this)`，早于 `runServer`→`initServer`→`createLevels`→`createBiomes`，故此时 RegistryAccess 已含完整 dynamic biome 注册表。
- 首次成功解析时缓存 `Registry<Biome>` 到静态字段，后续调用复用（稳健）。
- 兜底：无服务器时仍试 `ForgeRegistries.BIOMES`（客户端/晚于同步的路径）。
- runClient 目检（待做）。

## 创建世界卡死在 0%：ConcurrentHashMap 死锁 + 竞态

- **现象**：19 个 Worker 线程各自打印 "terrain engine initialized" 后日志终止，无 crash 但进程冻结。
- **根因 1（致命）**：`GeoGenesisTerrain.generateChunk` 末尾 `if (cache.size() > CACHE_SIZE) { cache.keySet().iterator().remove(); }`——该函数是 `cache.computeIfAbsent(key, k -> generateChunk(...))` 的 lambda。ConcurrentHashMap 的 `computeIfAbsent` 禁止在映射函数内修改同一 map（会死锁）。即使 cache 未超 256 不实际执行删除，但该代码路径仍在 computeIfAbsent 保留锁期间被扫描，多线程竞争时可死锁。
- **修复 1**：移除 generateChunk 内的 LRU 淘汰，抽为独立的 `pruneIfNeeded()` 在 `getChunkCells` 的 computeIfAbsent 外部调用。
- **根因 2**：`getOrInitTerrain()` 用 `if (sharedTerrain == null)` 竞态检查（volatile 不足原子化），19 线程同时进入 → 19 次重复初始化。
- **修复 2**：改为双重检查锁定 `synchronized(GeoGenesisGenerator.class)` 确保只创建一个共享引擎。
- 编译通过（BUILD SUCCESSFUL）。
