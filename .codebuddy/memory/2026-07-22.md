## 双曲线雪线模型（温度×湿度）实现完成

### 变更摘要
实现双曲线雪线图表，SNOW 类型判定接入湿度条件。

### 新建文件
- **`SnowLineChart.java`**（`client/preview/mixer/`）：双曲线雪线图表组件
  - 干燥曲线（橙色，湿度=-1）和湿润曲线（蓝青色，湿度=+1）并行显示
  - 两线之间渐变填充（上橙下蓝）表示湿度影响范围
  - 4 个方形控制点：干燥冷端/暖端、湿润冷端/暖端
  - 配对交互：拖干燥点调整中线+温度敏感性，拖湿润点调整湿度带宽
  - 约束：干≥湿（不交叉），冷≤暖

### 修改文件
- **`TerrainParams.java`**：新增 `snowHumidityInfluence` 字段（默认0.15）
- **`GeoGenesisConfig.java`**：新增 `snowHumidityInfluence` 配置字段（范围[0,0.5]，默认0.15），同步 buildParams/defaultParams/resetToDefault
- **`ParameterConfigPanel.java`**：用 SnowLineChart 替换旧的 SingleCurveChart，3个滑块（寒带中心、暖带中心、湿度带宽）
- **`CellGenerator.java`**：`classify()`/`classifyTerrain()` 加 humidity 参数，SNOW 判定用双曲线模型（雪线= base + (tNorm-0.5)×tempInf - (hNorm-0.5)×humInf）替代旧温度样条硬阈值
- **`GeoGenesisTerrain.java`**：`classifyTerrain` 调用加 humidity 参数

### 第三次迭代：修复重置后参数变 205 + 曲线变水平

**问题**：点击雪线滑块重置后，各参数显示 205，两曲线变水平线。

**根因**（两个 bug 叠加）：
1. `defaultValue` 公式用旧线性映射：`0.70×(320-(-64))+(-64)=205`，应为海平面锚定：`0.70×(320-63)+63=243`
2. `onReset` 只调 `refreshPoints()`，但 `ParamSlider.resetToDefault()` 先执行的 `onChange.accept(205)` 已把配置写坏。依次点击三个重置导致级联污染：tempInf→0 → 曲线水平

**修复**：
- `defaultValue` 公式改为 `c.snowLine.getDefault() * landRange + seaLev`
- `onReset` 恢复全部三个配置字段到真默认值（覆盖 onChange 写入的错误值）再刷新图表
- 编译 BUILD SUCCESSFUL in 29s

### 第四次迭代：世界高度与雪线之间 60+px 空隙

**问题**：用户截图显示世界高度滑块与雪线标题之间有大段空白（红色椭圆区）。

**根因**：`MixerPanel.contentH` 设的过大。世界高度面板声明 240px，但实际内容只占 ~178px（heightBar 100 + gap 16 + 3 sliders 62），多出 60+px 空白卡在最后滑块和雪线标题之间。雪线面板也有 12px 不足（声明 170，实际 182），滑块溢出。

**修复**：
- `heightPanel.setContentHeight(240) → 180`（heightBar 100 + gap 16 + sliders 62 = 178 → 180 含 padding）
- `snowPanel.setContentHeight(170 → 182)`（chart 100 + buffer 4 + sliders 66 + padding）
