## 配置修正循环修复

**问题**：拖拽海洋控制点时，其他类型控制点位置跳动（误以为"拖 A 影响 B"）。

**根因**：海洋 depth 配置字段范围 `[-1, 0]`，但滑块范围 `[-1, 1]`。拖到正数区域 → Forge 文件监控发现超范围 → 自动修正回 0.0 → 所有海洋控制点视觉跳回。

**修复**：
1. 海洋滑块 max 从 `1.0` 改为 `0.0`（`slMax = (i < 4) ? 0.0 : 1.0`）
2. 海洋 slot setter 加 `clampDepth(v)` 防御（覆盖图表控制点路径）

**编译**：BUILD SUCCESSFUL in 14s ✅

## 海洋控制点反转 + 耦合修复（v2）

**问题 1**：lo > hi（最小值大于最大值）。例：浅海 slot lo=0、hi=-0.25，反转显示。

**问题 2**：拖动滑块影响其他类型。海洋 slot 共享深度字段（深海.hi=浅海.lo=deepOceanDepth），但拖一个滑块时图表耦合点不同步，用户感觉在动其他类型。

**根因**：
- 海洋 setter 之前只 clamp 到 [-1, 0]，没考虑相邻 slot 的邻接约束（`deepOcean ≤ shelf ≤ shallow`）
- 图表控制点拖拽时只更新拖动点位置，耦合的相邻控制点要等松手后才刷新
- 滑块拖动时图表控制点也只通过 `refreshFromConfig()` 读陈旧值更新

**修复**：
1. `oceanSlot` setter 加邻接约束（`clampOceanLo`/`clampOceanHi`）：写入时动态读相邻值作为 clamp 边界
2. `DualRangeChart.mouseDragged` 加图表拖拽 clamp：实时阻止越界
3. `DualRangeChart.updateControlPoint` 新方法：按 e 值直接更新指定控制点
4. 滑块 onChange 改为 `chart.updateControlPoint` 实时同步（替换旧的 `refreshFromConfig` 读陈旧值）
5. chart.setOnValueChanged 也调用 `updateControlPoint` 同步耦合控制点

**编译**：BUILD SUCCESSFUL in 14s ✅
