### 用户需求

2. 湖泊在边界处有阶梯错位断裂（第三张图）

### 分析过程
1. 启动 code-explorer 子代理全面探索相关文件
2. 读取 CellGenerator、HeightCurve、GeoGenesisTerrain、HydraulicErosion、TileLakeSolver 关键代码段
3. 分析根因并提出修复方案

### 发现的根因

#### 海岸线断裂根因
1. **landCoastFactor 乘法模型在 c≈0 时 ∝c²**：`smooth(clamp(c/0.25))` 在 c 很小时近似为 48c²，导致海岸附近高度变化极慢，形成平台。
2. **海洋/陆地梯度不对称**：海洋侧 e 变化约 0.01/block，陆地侧仅约 0.00047/block，梯度差约 20 倍。
3. **landShape 控制点低 e 段斜率不足**：第一段 Y 仅从 0→0.06，高度变化有限。
4. **horizontalScale>1 时海岸过渡带被降采样吞掉**。

#### 湖泊接缝根因
1. **priority-flood 从 region 外边界出发**：不同 tile 的边界不同 → 同一洼地湖面不同。
2. **HydraulicErosion interior=gsz-16，PAD=64**：水滴在 PAD 内部活跃流动，边界截断不一致。
3. **carvedE 在 PAD 边界处因水滴流向被截断产生 tile 间差异**。

### 修复方案（待用户确认）

#### 海岸修复方案
1. **改用加法模型替代乘法模型**：`e = c + (1 - lm) * eLand * lm`，保证 c=0 时 e=0。
2. **调整 landCoastFactor 带宽**：从 0.25 改为 0.15，使海岸更陡。
3. **抬高 landShape 低 e 段斜率**：调整控制点使近岸陆地抬升更快。

#### 湖泊接缝修复方案
1. **扩大侵蚀 interior 边界**：从 gsz-16 改为 gsz-2*PAD，避免水滴在 PAD 内部活跃。
2. **调整 priority-flood 洪泛起点**：确保相邻 tile 的洪泛起点一致。
3. **统一 carvedE 在 PAD 边界的处理**。

### 修复完成（2026-07-11 13:48）

#### 海岸断裂修复
1. **landCoastFactor 改为线性模型**：从 `smooth(clamp(c/0.25))` 改为 `clamp(c/0.15)`

## 海岸平台根治：乘法淡出 → 海陆线性混合（2026-07-11 20:xx）

### 问题（用户第三次反馈）
即使改为线性 lm（二次修复），海岸仍有平台：陆地侧 + 海洋侧 2 格宽海平面平台；河流在海洋区域平台流淌。

### 根因（对比旧版 backup 后确认）
- 当前版用**乘法淡出** `e = eLand * lm`，`lm` 在海岸→0 把陆地振幅乘没 → 海陆塌到海平面平台。
- 旧版 backup `GeoGenesisGenerator.computeHeight` 用**世界高度线性混合**：
  `transition = smoothstep((c+0.4)/0.8)`；`landHeight = seaNorm + shaped*range*amp`（满振幅）；
  `oceanHeight = seaNorm - oceanDepthFactor*(1-t)`（被 (1-t)² 压低）；
  `result = oceanHeight*(1-t) + landHeight*t`。
  → 陆地不归零、海洋被压在水面下 → 海岸处半海半陆、海平面极窄穿过，**无平台**。

### 修复（忠实复刻旧版，迁到 e 空间）
`CellGenerator` 新增 `blendE(c, eLand, x, z)`：
```
t = smoothstep(clamp((c+0.4)/0.8, 0, 1))          // 与旧版一致（COAST_BAND=0.4）
e = -OCEAN_E*(1-t)² + eLand*t + OCEAN_DETAIL*d*(1-t)   // OCEAN_E=1, OCEAN_DETAIL=0.03
e = clamp(e,-1,1)
```
- 丢弃 `COAST_LAND_BAND` / `landCoastFactor`（乘法淡出）。
- `computeShape` / `shapeE` / `landHeight` 三处统一调用 `blendE`；`dominantTerrain` 改 `e>=0 ? classifyLand : OCEAN`；`landHeight` 对 e<0 返回 NaN（不刻蚀入海）。
- 深海细节 `OCEAN_DETAIL*d*(1-t)`：海洋侧生效，乘 (1-t) 保证永不翻正成陆地。

### 数值验证（eLand=0.5）
- c=0 (t=0.5): e=-0.25+0.25=0 → 海岸单线海平面
- c=0.1 (t=0.683): e≈0.24 陆地；c=-0.1 (t=0.297): e≈-0.35 海
- 跨海面极窄（±0.05c 内 e 由 -0.1 到 +0.23），无宽平台；河流顺混合 e 入海

- `CellGenerator.java`：COAST_BAND/OCEAN_E/OCEAN_DETAIL + blendE + smoothstep；computeShape/shapeE/landHeight 改写
- `HeightCurve.java`：注释更新（landCoastFactor → 海岸混合）

## 海岸连续样条重构 v5（2026-07-11 深夜）

### 问题
用户指出"陆地地形是不受大陆性影响的"，并要求：
1. 不要分段（if/else），一个整体样条
2. 陆地地形不受 c 影响（内陆 e = eLand）
3. 海洋深度由 c 决定
4. 海岸平滑过渡

### 根因
之前的 `blendE` 有 if/else 分支：
- 海洋（c<0）：e = c + OCEAN_DETAIL*d*(1-t)
- 陆地（c≥0）：e = eLand × coastFade

这违反了"不要分段"的原则，且 coastFade 在 c=0.03 时仅 0.08，导致 eLand×0.08 掉入 landShape 死区（e<0.04），形成海岸平台。

### 新设计（连续样条 + lerp）
```java
// 整体样条：c → baseE（无 if/else）
double baseE = NoiseUtil.spline(c, HEIGHT_C, HEIGHT_E);
// 陆地权重：c<0→0，c>0.15→1
double landW = smoothstep(NoiseUtil.clamp(c / 0.15, 0.0, 1.0));
// 混合
double e = NoiseUtil.lerp(baseE, eLand, landW);
// 海洋细节
e += OCEAN_DETAIL * d * NoiseUtil.saturate(-c);
```

### 样条控制点
| c | baseE | 说明 |
|---|-------|------|
| -1.0 | -0.6 | 深海 |
| -0.5 | -0.3 | 大陆坡 |
| -0.16 | -0.12 | 大陆架 |
| 0 | 0 | 海平面 |
| 0.15 | 0.12 | 近岸缓坡 |
| 0.5 | 0.5 | 内陆 |
| 1.0 | 1.0 | 高地 |

### 关键特性
- c=0 → baseE=0, landW=0 → e=0（海平面）✓
- c=0.15 → landW=1 → e=eLand（满地形起伏）✓
- c=-0.5 → landW=0 → e=baseE=-0.3（海洋深度）✓
- **陆地地形不受 c 影响**（内陆 e=eLand）✓
- **无 if/else 分支**，一个整体样条 ✓

- `CellGenerator.java`：blendE 重写为连续样条 + lerp
