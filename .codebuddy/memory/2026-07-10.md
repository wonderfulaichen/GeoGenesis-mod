## RiverSCA 黑屏 Bug 修复（吸引子过稀 + 根节点过严）

**问题**：RIVER_NETWORK 图层整个黑屏。调试发现：1200×1200 区域仅449个吸引子（attractorDensity=0.5→step=22），
每个节点感知半径12格内平均仅~0.14个吸引子 → 30个根节点大多立刻停止 → 仅14个河段，对300×300=90000 cell 几乎不可见。

**根因**：
1. 吸引子密度过低（step=22，感知半径12格内预期<1个吸引子）
2. `collectRoots` 中 `hasHigherNeighbor` 检查过严（边界低地无更高邻居时被过滤）
3. 生长循环 `cnt==0` 时直接停止，无吸引子时河流无法延伸

**修复**（3处）：
1. **提高 SCA 默认参数**（`RiverSettings.java`）：attractorDensity 0.5→2.0（step 22→11），attractDist 12→20，killDist 3→4，stepLen 6→5
2. **放宽根节点条件**（`RiverSCA.collectBorder`）：移除 `hasHigherNeighbor` 检查，边界低地直接作 root
3. **Orphan Branch 机制**（`RiverSCA.grow`）：`cnt==0` 时不再停止，沿纯上坡方向继续生长（`MAX_ORPHAN_STEPS=12`），子节点继承 orphanSteps；
   回退 root 逻辑改为取**所有**低地吸引子（而非仅取最低1个）

**验证**：`gradlew compileJava` BUILD SUCCESSFUL。请 `gradlew runPreview --args=12345` 验证河网可视化。

## RiverSCA "缺主干大河、只有局部小溪" 调参（第二次迭代）

**问题**（用户目检反馈）：河网比黑屏好，有河流感，但"还是很局部，没那种大河"——全是细溪，无主干大河。

**诊断**（生成阶段问题，渲染层正常）：
1. 出口 root 过多（旧逻辑 ≤96 个沿边界密集撒点）→ 每出口流域太小 → 主干汇水量 `order`（=子树吸收吸引子数）低 → 河宽 `1.5+√order` 小 → 全是细溪。
2. `MAX_ORPHAN_STEPS=12` 太小 → 局部吸引子吸完后主干最多爬 12 步(≈60格)就停，主干被截短成局部水沟。
3. `attractDist=20` 偏小 → 每步生长方向短视、树枝发散、不易沿谷汇成主干。

**修复**（`RiverSCA.java` + `RiverSettings.java`）：
1. 出口 root 改用**远点贪心稀疏**（`collectRoots` 重写）：候选按海拔排序，首根取最低；后续每根取「离已选根最远且 ≥MIN_ROOT_SPACING(170 block) 且尽量低」者，上限 `MAX_ROOTS=16`。→ 每出口大流域 → 主干 order 暴涨 → 大河。
2. `MAX_ORPHAN_STEPS` 12→40，主干向上游延伸更远、吸更多支流。
3. `attractorDensity` 保持 2.0（防黑屏）；`attractDist` 20→26（生长更具方向性、易沿谷汇主干）。

**验证**：`gradlew compileJava --rerun-tasks` BUILD SUCCESSFUL。待用户 `gradlew runPreview --args=12345` 目检验证大河形态。

**说明**：orphan branch 目前纯上坡+侧向抖动，不沿谷下行；若个别出口流域内吸引子离根过远(>orphan 40步≈200格)仍可能截短，但少而大的流域设计下多数出口会有大河。若仍偏细，下一步可考虑：降低 attractorDensity 至 1.5 让主干更突出、或提高 WIDTH_SCALE 让主干视觉更粗。

## 独立预览窗口"加载新区域卡死/一直刷新不了"修复

**问题**（用户目检反馈）：`gradlew runPreview` 窗口加载新区域有概率直接卡住、一直刷新不了。

**根因（两个叠加）**：
1. **采样分辨率随缩放平方爆炸（主因）**：`TerrainPreview.render` 原按 `cellsX = 600*scale/horizontalScale` 采样，`horizontalScale=4`。缩放越小(scale越大)区域越大而渲染像素恒为 600×600 → 严重过剩采样。scale=64 时 cellX≈9600 → 近亿 cell × `populate`（大量噪声）→ 几分钟到卡死。这就是"概率卡"（只在缩小/拉远时出现）。
2. **河网 O(n²) 扫描**：`RiverSCA.grow` 合并检测 O(nodes²)、吸引子扫描 O(nodes×attractors)，大区域也会爆。
3. **加载器丢失请求**：`scheduleCompute` 在 `computing` 时直接 return，平移期间最新区域请求被丢弃；虽 finally 的 repaint 会补救，但叠加(2)的慢算会长时间显示旧区域像"卡死"，且无进度提示。

**修复**：
- **采样与缩放解耦**（`GeoGenesisTerrain.getRegionCells` 新增 `cellStep` 重载，原 4参/带 onProgress 兼容重载保留供 PreviewDisplay）：`cellsX = PANEL/质量档`（恒 ≤600），`cellStep = scale*质量档`，采样/河网/栅格化改用 cellStep 映射世界坐标。成本恒定为 ~36万 cell，与缩放无关。
- **河网空间哈希**（`RiverSCA`）：新增 `HASH_CELL=28`（≥attractDist/killDist），`buildAttrHash` + 每迭代重建节点哈希；吸引子求和与合并检测改查 3×3 邻域哈希 → 复杂度 O(nodes)（即 memory 中标记的"性能 follow-up"已落地）。
- **加载器健壮化 + 进度**（`TerrainPreview`）：`scheduleCompute` 用 `reqObx/reqObz/reqCellsX/reqCellsZ/reqCellStep` 记录最新待算区域；算完若请求已变则自动续算最新区域（绝不丢请求、无活锁）；接线 `onProgress` 在"加载中"界面画百分比进度条（`drawProgress` + `maybeRepaintProgress` 节流 5%），不再像冻死。移除未使用的 `horizontalScale` 字段。

**验证**：`gradlew compileJava --rerun-tasks` BUILD SUCCESSFUL。待用户 `gradlew runPreview` 验证：缩小到最大(scale=64)拉远也不应卡死，加载界面有百分比进度。

## 预览窗口"河流缩放消失 + 跳闪 + 漂移"三连修

**问题**（用户目检反馈，截图确认）：1) scale=0.25（放大）时河流橙线可见，缩放后（scale 变大）河流完全消失（只剩蓝色点状水体）；2) 拖动/缩放时画面跳闪一下；3) 移动到想看的位置后画面会随机漂移偏离。

**根因分析（三个独立 bug 叠加）**：
1. **河流消失（主因）**：`GeoGenesisTerrain.rasterizeRiver` 用 `hs = cellStep` 投影 → scale 大（拉远）时 hs 大 → cell center 到河段距离 `bestD` 远超河流原始宽度 → `riverNetDist = bestD/(width*falloff)` 接近 1 → 河流不可见。**不是河流没生成，是栅格化精度随 scale 降低导致丢失。**
2. **跳闪**：`TerrainPreview.render` 的 `needsCompute` 分支把 `cachedCells = null` → compute 期间无数据可渲染 → 黑帧/空帧闪烁，compute 完成后画面突变。
3. **漂移**：`cachedCells` 置 null + `originBlockX = floor(originX)` 的 1-block 量化偏移 → 缩放后新旧区域网格不对齐 → 画面跳 1-block。

**修复**：
1. **河流缩放不消失**（`GeoGenesisTerrain.rasterizeRiver`）：新增 `widthScale = max(1.0, cellStep/4.0)`，`effectiveWidth = best.width * widthScale`，`rd = bestD / (effectiveWidth * falloff)`。缩放后河流视觉宽度按比例放大，确保粗网格上仍可见；`riverNetWidth` 保留原始值供游戏逻辑。当 cellStep=32 时 effectiveWidth 放大 8 倍，bestD=16 → rd=0.42 < 1.0 ✓。
2. **消除跳闪**（`TerrainPreview.render`）：`needsCompute` 分支**不再置空 `cachedCells`**，保留旧图作底 → compute 期间画旧帧平滑过渡（lastFrame affine 变换），完成后无缝替换 → 无黑帧闪烁。
3. **漂移**：光标中心缩放已让 origin 偏移最小化（最多 1-block），叠加(2)不再置空 cachedCells → 旧帧过渡填补 compute 间隙 → 视觉上无跳变。

**验证**：`gradlew compileJava --rerun-tasks` BUILD SUCCESSFUL。待用户 `gradlew runPreview` 验证：滚轮缩放后河流仍可见（橙线不消失），拖动/缩放无跳闪，画面不漂移。

> ⚠️ **更正（本次重写）**：上面 2026-07-10 的"三连修"根因判断**错误**，用户实测河流消失/漂移**未修复**。
> 真正的根因在 `RiverSCA`（预览专用河网），不在 `rasterizeRiver` 的栅格化：
> 1. **漂移**：`computeRegionRiver` 的河网种子 `rs = seed ^ obx*k ^ obz*m` 由**区域原点 obx/obz 派生**；平移/缩放让 `originBlockX/Z` 一变 → 区域种子整体翻转 → 每次重算一套**全新**河网 → 河流乱跳/随机漂移。地形 `cellGen.populate` 是全球确定性的，所以只有河流在跳。
> 2. **消失**：`scatterAttractors` 用**固定步距格点 + 全局 `rnd()` 序列 + 原 `MAX_ATTRACTORS=6000`**；缩小时区域巨大（数万方块）→ 视野内吸引子极稀疏 → 河网几乎为空 → 河流消失（非栅格化精度问题）。
>
> **真正修复（RiverSCA + computeRegionRiver）**：
> - 河网种子改 `rs = seed * 2654435761L`（只用世界 seed，去掉 obx/obz）→ 不再随视图原点重置。
> - 吸引子/出口格点**对齐世界原点**（`startX=floor(x0/step)*step`）→ 平移时只增删边缘行、内部稳定。
> - 撒点抖动/接受判定/生长侧向抖动全部改用**位置哈希 `phash(x,z,salt)`**（平移缩放不变），删除全局 `rnd()`/`rngState`。
> - **自适应格距** `step = max(5, sqrt(area / TARGET_LATTICE))`，`TARGET_LATTICE=20000` → 区域内吸引子总数恒定 → "视野内河流数"在任意缩放下恒定 → 缩小时河流不消失；`MAX_ATTRACTORS` 提到 60000 作安全上限。
> - 保留 `rasterizeRiver` 的 `widthScale`（细河在粗网格仍可见），属锦上添花。
>
> **结论**：河流现成为全球坐标的确定性函数，平移不重算新网（不漂移），缩放不消失。编译 BUILD SUCCESSFUL。待 `runPreview` 实机目检。

## 修复 droplet 侵蚀 region 边界断裂 + 台阶地形（2026-07-10 傍晚）

**用户反馈**（实机目检）：
1. 512 边界有明显断裂线（图1）
2. 高度断崖（图2）
3. 地形呈台阶状（图3）
4. 边界之间各自为政，不交流（图4）

**根因分析**：
1. **边界断裂**：相邻 region 独立跑 droplet 侵蚀，无共享信息。`buildErosionRegion` 的 `originBX = regionX * 512`，相邻 region 网格无重叠，边界处 droplet 结果完全不同。
2. **高度断崖**：`sampleHeight` 中 `Math.round((worldX - originBX) / cellStep)` 的取整映射导致 worldX 到 cell 索引的离散跳变，加上相邻 region 的侵蚀结果差异 → 断崖。
3. **台阶地形**：`sampleHeight` 使用最近邻 cell 索引（无插值），每个 cell 覆盖 2×2 blocks，导致高度每 2 blocks 阶梯跳变。
4. **坐标偏移**：`sampleHeight` 的 `originBX` 映射与 `buildErosionRegion` 不一致，导致额外偏移。

**修复**：
1. **padding 重叠**：`buildErosionRegion` 增加 `PAD_CELLS=32`（64 blocks），`originBX = regionX*512 - 64`，网格大小 `256 + 64 = 320`。相邻 region 重叠 128 blocks，共享边界采样。
2. **双线性插值**：新增 `bilinear()` 方法，`sampleHeight` 和 `applyErosionToCell` 从最近邻改为双线性插值，消除 2-block 台阶。
3. **边界混合**：新增 `sampleErosionELand()`，在 `BLEND_CELLS=16`（32 blocks）边界范围内，与相邻 region 侵蚀结果做加权平均（权重基于距离边界的比例）。四方向（左/右/上/下）独立混合后取平均。
4. **线程安全**：`getOrBuildErosionRegion()` 加 `synchronized` 锁，防止并发重复构建；`erosionCache` 改为 `ConcurrentHashMap`。
5. **缓存限制**：`EROSION_CACHE_LIMIT` 从 512 降为 64（320×320 grid 每 region 约 1.4MB，64 个约 90MB）。
6. **统一路径**：`computeChunkCells` 和 `getRegionCells` 统一使用 `applyErosionToCell`（调用 `sampleErosionELand`），不再直接读取 `er.carvedELand[][]`，确保所有采样路径都走边界混合。

**验证**：`gradlew compileJava` BUILD SUCCESSFUL。待用户 `gradlew runClient` 实机目检边界连续性。

## Region 边界断裂深入分析（2026-07-10 19:23）

**用户报告**：512-block region 边界断裂——相邻 region 一侧是深海+山脉，另一侧是平坦陆地，交界呈直线。

**分析重点**：
1. **噪声采样确定性**：`cellGen.shapeE(worldX, worldZ)` 是确定性的，因为所有噪声函数（SimpleContinent、StructuralField、TerrainBlender）都是纯函数，只依赖世界坐标和种子。同一世界坐标在不同 region 中应返回相同结果。
2. **坐标映射**：`RiverField.computeRegion` 中 `gsz = size + 2 * PAD`，`ox = obx - PAD`，`oz = obz - PAD`。采样循环 `int wx = ox + i, wz = oz + j; float e = (float) cellGen.shapeE(wx, wz);` 正确。提取结果时 `h[PAD + j][PAD + i]` 对应世界坐标 `(obx + i, obz + j)`，索引映射正确。
3. **Region 边界混合逻辑（缺失）**：无任何 region 边界混合逻辑。每个 region 独立计算侵蚀结果，然后直接拼接。
4. **侵蚀独立性**：`HydraulicErosion` 水滴模拟在 padding 边界处被截断（`if (ix < 1 || ix >= gsz - 2 || iy < 1 || iy >= gsz - 2) return;`），水滴不会跨越 region 边界。
5. **平滑操作边界效应**：`smoothErosionResult` 只在 `start=pad+radius` 到 `end=pad+gsz-2*pad-radius` 之间平滑，边界区域不平滑。

**可能根因**：
1. **侵蚀结果独立性**：每个 region 独立计算侵蚀，导致边界处流量场和刻蚀深度不连续。
2. **平滑操作边界效应**：边界区域未平滑，导致高度突变。
3. **用户报告场景**："一侧深海+山脉，另一侧平坦陆地" 可能是由于相邻 region 的侵蚀结果差异（一侧强侵蚀形成河谷，另一侧弱侵蚀保持平坦），但侵蚀只影响陆地，不影响海洋深度。海洋深度由 `shapeE` 决定，应该是确定性的。

**建议修复方向**：
1. **增大 padding**：确保水滴可跨越 region 边界。
2. **边界混合**：在 `applyRiverFields` 或 `computeRegion` 中对边界侵蚀结果插值。
3. **统一平滑区域**：修改 `smoothErosionResult` 以包含 padding 区域。

## 关键发现：索引转置错误（2026-07-10 19:30）

**发现**：`RiverField.computeRegion` 和 `GeoGenesisTerrain.sampleHeight` 之间存在索引转置错误。

**`RiverField.computeRegion` 中**：
```java
for (int j = 0; j < sz; j++) {      // j = z 偏移
    for (int i = 0; i < sz; i++) {   // i = x 偏移
        finalY[j][i] = ...;          // 数组索引 [z偏移][x偏移]
    }
}
```

**`GeoGenesisTerrain.sampleHeight` 中**：
```java
int i = worldX - r.obx;  // i = x 偏移
int j = worldZ - r.obz;  // j = z 偏移
return r.finalY[i][j];   // 数组索引 [x偏移][z偏移]
```

**错误**：`sampleHeight` 使用 `[x偏移][z偏移]` 访问，但数组存储为 `[z偏移][x偏移]`。这导致坐标转置。

**同样错误存在于 `applyRiverFields`**：
```java
cell.riverMask = r.riverMask[i][j];  // 使用 [x偏移][z偏移]
```

**影响**：
- region 内部自洽：每个 region 内部所有采样都使用相同的转置错误，所以内部连续。
- region 边界不连续：相邻 region 的转置错误可能导致边界处高度和河流不连续。

**建议修复**：在 `sampleHeight` 和 `applyRiverFields` 中，将 `r.finalY[i][j]` 改为 `r.finalY[j][i]`，同样修复 `r.dis[i][j]`、`r.riverMask[i][j]` 等。
