## 修复：MC 地形预览全黑（PreviewDisplay 不显示）

根因（两层）：
1. `PreviewDisplay` 构造器原本未调用 `requestResample()`，纹理永远是空的（`hasTexture=false`）。已在上一轮补上。
2. 真正的崩溃点：`LakeGenerator.generateLakes` 把网格当**正方形**（`Math.max(cellsX, cellsZ)` 当边长），并用 `cells[z][x]`（第一维当 z）访问，但 `getRegionCells` 创建的网格是 `new Cell[cellsX][cellsZ]`（第一维是 x）。预览控件**非正方形** → 循环越界抛 `ArrayIndexOutOfBoundsException` → 后台采样线程异常被 `catch` 静默吞掉 → `hasTexture` 永不置真 → 全黑+图例。
   - 为什么 Swing 预览正常：Swing `TerrainPreview` 是 600×600 正方形（`cellsX==cellsZ`），不触发越界。
   - 顺带修正了 in-game chunk 生成的湖泊坐标被转置的潜在 bug（`computeChunkCells` 同样走 `generateLakes`）。

修复：
- `LakeGenerator`：`generateLakes` 改为接收 `cellsX, cellsZ`，全部索引改为 `cells[x][z]` 并按各自维度边界检查；`findDepressions`/`fillLakes`/`fillArea`/`visited`/`isDepression` 数组同步改为 `[cellsX][cellsZ]`。
- `GeoGenesisTerrain`：`computeChunkCells` 传 `(n, n)`，`getRegionCells` 传 `(cellsX, cellsZ)`。
- `PreviewDisplay`：新增 `lastError` 字段，后台线程/`mc.execute` 异常时记录并在预览区顶部以红字显示，避免再次出现"黑屏无信息"。

验证：`compileJava` BUILD SUCCESSFUL，无 lint 错误。需 `runClient` 实机确认地形纹理出现。

## 修复：拖动预览后图片“飘出去”

根因：`PreviewDisplay.renderWidget` 只在 `done=false`（重采样中）时才对旧纹理做仿射映射；`done=true` 时直接铺满控件。用户拖了一段距离后触发重采样，旧纹理从“拖前视口”一下子映射到“当前视口”，看起来像飘出控件。

修复：把纹理绘制统一为**始终按 `texOriginBlockX/Z` + `texScale` 仿射映射到当前视口**。拖拽/缩放期间画面连续跟随，重采样完成后再换上清晰的新纹理并 snap 到位。

验证：`compileJava` BUILD SUCCESSFUL。

## 雪线模型最终修正（用户反馈）

用户提出："或者我们这个雪线换成更合理的标准和描述，因为极寒地形是到处都是雪"。

**最终模型**:
- `coldSnowLine = seaLevel + 2`（极寒：雪线降到海平面附近，冻原/冰盖到处是雪）
- `warmSnowLine = snowLine + (mountainCap - snowLine) * k`（热带：雪线往上升，仅最高峰有雪）
- `effSnow = coldSnowLine + cell.temperature * (warmSnowLine - coldSnowLine)`

**语义变更**:
- `snowLine` 从"最低雪线高度"改为"温带标准雪线高度"（可配置，例如 Y=100）
- 极寒 `temp≈0` → `effSnow≈seaLevel`（海平面以上全是雪，冻原/冰盖效果）
- 温带 `temp≈0.5` → `effSnow` 在中间值
- 热带 `temp≈1` → `effSnow` 升到 `snowLine + (mountainCap-snowLine)*k`（仅最高峰有雪）

**方案更新**:
- `TERRAIN_TYPE_SCHEME.md` §4.5 已更新公式和注释
- 默认 `k=0` 时 `warmSnowLine = snowLine`，极寒→热带的雪线范围为 `[seaLevel+2, snowLine]`，仍有温度调制效果（极地到处是雪）
- `effSnow` 天然不低于 `seaLevel+2`，无需额外钳制

  - 确保 tooltip 不超出屏幕顶部（`ty < 0` 时设为 0）
- 这样 tooltip 会完全显示在滑块上方或下方，避免与数字文本重叠

## 崩溃修复：调音台拖拽控制点写盘导致崩溃（2026-07-09 07:41）

## Scissor 裁剪参数修复（2026-07-09 15:07）

**问题**：参数页自定义组件（SnowLineChart/WorldHeightBar/ScalePreview）内容仍然溢出到标签页头部上方（截图确认：Y轴标签、图例、曲线全部渲染在"参数"标签上方）。

**根因**：`RenderSystem.enableScissor(x, y, width, height)` 参数是 `(x, y, 宽度, 高度)`，但代码传入 `(clipX, clipY, clipX2, clipY2)` — 把右下角的**绝对像素坐标**当成了**宽高**。实际裁剪区域远大于面板（例如宽度传入了 X₂=800 而非实际面板宽=280），等于**完全没有裁剪**。同样的 bug 在 `BasicParamsPanel` 和 `TerrainConfigPanel` 中都存在。

**注意**：`PreviewDisplay.java` 中的 `g.enableScissor(x1,y1,x2,y2)` 是正确的，因为 `GuiGraphics.enableScissor` 接受 `(x1,y1,x2,y2)` 并内部转换为 `(x,y,w,h)`。只有直接调用 `RenderSystem.enableScissor` 的地方才有此 bug。

**修复**：
- `BasicParamsPanel.renderWidget()`：`RenderSystem.enableScissor(clipX, clipY, clipW, clipH)` — `clipW = getWidth() * guiScale`, `clipH = (getHeight() - PAD - headerH) * guiScale`
- `TerrainConfigPanel.renderWidget()`：`RenderSystem.enableScissor(clipX, clipY, clipW, clipH)` — `clipW = getWidth() * guiScale`, `clipH = (getHeight() - HEADER_H - GAP) * guiScale`

**涉及文件**：`BasicParamsPanel.java`、`TerrainConfigPanel.java`
**验证**：`gradlew.bat compileJava` → BUILD SUCCESSFUL
