## 地形类型分配重建：Voronoi+Catmull-Rom → 连续权重场+TypeGenerator

### 问题诊断
用户报告地形断裂（等高线纹理），诊断为 Voronoi 胞边界 type 硬跳变导致 relief 振幅突变（±0.28 e → ~28 块高度差），叠加 TYPE_OFFSET 跳变 0.22，总跳变可达 0.5 e ≈ 50 块垂直墙。

### 解决方案
删除 VoronoiTerrain + TerrainColormap，重建为连续权重场 + TypeGenerator 加权合成：

1. **删除文件**：VoronoiTerrain.java、TerrainColormap.java
2. **移除参数**：GeoGenesisConfig 和 TerrainParams 中的 voronoiCellSize
3. **新建 ClimateWeights**：气候空间高斯基函数 × 省权重增益 → 连续权重
4. **新建 TypeGenerator 接口 + 5 个生成器**：
   - PlainGenerator：1/900 FBM，振幅 0.04
   - HillsGenerator：1/350 双层 FBM，振幅 0.12
   - PlateauGenerator：flat-top 台阶 + 边缘陡崖噪声，振幅 0.06
   - BasinGenerator：内凹 dome，振幅 0.06
   - MountainGenerator：1/200 FBM×3 高频 relief（stub，Phase B 上空间殖民骨架）
5. **新建 TerrainComposer**：连续权重场 + TypeGenerator 加权合成，海洋区域 eLand=0
6. **修改 CellGenerator**：VoronoiTerrain → TerrainComposer

### 核心公式
```
typeWeight[i] = softmax(exp(-climateDist²/σ²) × provinceGain[i])
eLand = Σ typeWeight[i] × generator[i].sample(wx,wz,weights)
```

## 修复地形断裂和接缝问题（2026-07-15）

### 问题诊断
用户报告两个问题：
1. 类型之间接缝不自然（错位）
2. 海陆有断裂

### 根本原因分析
1. **海陆断裂**：`TerrainComposer.sample()` 中 `continent < 0` 时硬跳变返回 `eLand=0`，导致海岸线不连续
2. **类型接缝**：气候计算过于简化（温度仅基于 wz，湿度仅基于 continent），权重分布不自然；TypeGenerator 输出范围差异大（Plain 0-0.04 vs Hills 0-0.12），过渡区域高度差明显

### 修复方案
1. **海陆断裂修复**：
   - 移除硬跳变 `if (continent < 0.0) return new TerrainSample(0.0, ...)`
   - 添加 `smoothstep(continent, -0.1, 0.1)` 海洋遮罩平滑过渡
   - `eLand *= landMask` 使海岸线附近 eLand 渐变

2. **气候计算改进**：
   - 添加气候噪声扰动（低频 Simplex，频率 1/3000）
   - 温度：基础温度 + 0.3 振幅噪声扰动
   - 湿度：基础湿度 + 0.2 振幅噪声扰动（不同相位）
   - 打破完全水平的温度带，增加空间变化

3. **TypeGenerator 输出范围调整**：
   - 为每个生成器添加基底高度（BASE），确保输出范围有重叠：
     - PlainGenerator: [0.01, 0.05]（基底 0.01 + 振幅 0.04）
     - HillsGenerator: [0.03, 0.15]（基底 0.03 + 振幅 0.12）
     - PlateauGenerator: [0.02, 0.08]（基底 0.02 + 振幅 0.06）
     - BasinGenerator: [0.01, 0.07]（基底 0.01 + 振幅 0.06）
     - MountainGenerator: [0.05, 0.25]（基底 0.05 + 振幅 0.20）
   - 过渡区域加权平均更平滑，消除视觉接缝

### 编译验证
BUILD SUCCESSFUL in 15s，无语法错误。

## 正确方向修正（2026-07-15 下午）

### 错误路线
今天上午/中午实现了 ClimateWeights + TerrainComposer + TypeGenerator 体系，意图是"气候驱动地形类型分配"。但这完全违背了文档中 03-地形类型方案 §2 的核心原则：
> **地形 TYPE 分布保持弱气候偏置（北美大平原即反例，绝不能做成决定论映射）**

### 修正方案
回退到正确的架构：
1. **eLand 来自 LandShape**（TerraForged 分层叠加模型，省权重主导）
2. **地形类型分类**使用 `classifyTerrain(省权重 + eLand + 气候弱偏置)`：
   - belt 省主导 + eLand 高 → MOUNTAINS/PEAK
   - plateau 省主导 + eLand 高 → PLATEAU
   - basin 省主导 + eLand 低 → BASIN
   - 其他（craton 主导）→ eLand 高→HILLS，低→PLAIN
   - 气候弱偏置：极冷时丘陵阈值微降 0.03
3. **删除 8 个错误文件**：TerrainComposer.java、ClimateWeights.java、TypeGenerator.java、PlainGenerator.java、HillsGenerator.java、MountainGenerator.java、PlateauGenerator.java、BasinGenerator.java
4. **CellGenerator** 重写：`classify()` → `classifyTerrain()` 静态方法
5. **编译验证**：BUILD SUCCESSFUL（2026-07-15 下午）

### 最终架构（简洁、正确）
```
LandShape.sample(wx,wz,weights) → eLand    ← 省权重主导分层形态
CellGenerator.classifyTerrain(e, eLand, weights, temp) → terrainType
                                     ↑
                              气候仅弱偏置（不主导）
LandShape.seed() + CellGenerator.seed() → 播种（无 TerrainComposer）
```

## 地形类型系统最终修复（2026-07-15 晚）

### 问题
用户报告：1) 类型间悬崖（过渡区仅1格）2) 类型内部单调（每个类型只一种FBM）3) warp错误（强度12+hash2离散）

### 修复方案（三层分离架构）

#### 1. TypeMorphology 丰富化
- **删除错误 warp 方法**：移除 `hash2` + 强度12的warp，避免离散跳变
- **山脉内部多样性**：按省上下文分化三种形态：

  - plateau省主导 → 阶梯陡崖山（平顶+边缘陡崖）
  - craton省主导 → 圆顶老山（低缓起伏）
- **Peak 按省分化**：belt省→极尖峰，plateau省→平顶高峰
- **平原/丘陵删除 warp**：直接使用原始噪声，保持连续性

- **替换 smoothstep**：使用 `NoiseUtil.spline`（Catmull-Rom样条）实现C1连续过渡

- **消除悬崖**：相邻类型渐近过渡，不再1格硬切
