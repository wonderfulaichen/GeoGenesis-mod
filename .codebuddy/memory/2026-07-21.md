## 气候样条系统实现（ClimateSpline）

**需求**：用户指出"条件因素那些滑动点其实就是样条的控制点"，要求将离散阈值 boolean 判断替换为样条连续映射。温度/湿度要带纬度概念。

**设计**：每个条件维度（温度/湿度/大陆性）一条 1D Cubic Hermite 样条，阈值作为控制点，输出连续区域索引 + tent 函数权重。

**新增文件**：
- `ClimateSpline.java`（`worldgen/climate/`）— 气候样条工具类
  - `fromThresholds(double[])` 从阈值构建样条
  - `sample(raw)` → 连续区域索引
  - `zoneWeights(raw)` → 各区域权重数组（tent 函数，和=1）
  - `zoneWeight(raw, zoneIndex)` → 指定区域权重
  - 便捷工厂：`temperature()` / `humidity()` / `continentality()`
  - 区域常量：TEMP_FROZEN/COLD/MILD/WARM/HOT, HUM_DRY/SEMI/WET/HUMID, CONT_DEEP_OCEAN~DEEP_INLAND

**修改文件**：
1. `Climate.java` — 添加样条权重方法（frozenWeight/coldWeight/mildWeight/warmWeight/hotWeight/dryWeight/semiDryWeight/wetWeight/humidWeight + tempWeights/humWeights），boolean 方法委托给样条（权重>阈值→true）
2. `ClimateZone.java` — 气候带分类改用样条权重（A/E/B/C/D 基于 maxWeight 选择）
3. `CellGenerator.java` — SNOW 判定从 `temperature < -0.1` 改为 `temperatureColdWeight(temperature) > 0.35`，新增 `temperatureColdWeight()` 辅助方法

**编译**：BUILD SUCCESSFUL in 19s（全量编译 --rerun-tasks）✅

**纬度融入**：样条操作的是最终温度值，该值已包含纬度基值 `sin²(z)×2-1`、海洋性修正、海拔递减率。样条阈值控制点在不同纬度产生不同的区域索引，自然"带纬度"。

**编译**：BUILD SUCCESSFUL ✅

**问题**：最高点/海平面/世界底 三个滑块无顺序约束（max > sea > min）。

**根因**：`ParameterConfigPanel.addYSlider` 中通过 `heightSliders.size()` 决定使用哪种约束，但 `addYSlider` 末尾才执行 `list.add(ps)`。Lambda 在用户拖拽时运行，此时三个滑块都已添加完成，`size()` 总是 2 或 3，导致：

- 拖 min 滑块 → 无匹配分支（idx==3 不存在）→ 完全无约束

**修复**：
1. 用 `cfg` 字段引用识别滑块（`cfg == cc.maxY` / `cfg == cc.seaLevel` / `cfg == cc.minY`）替代 size() 索引
2. lambda 中 `psHolder[0].setCurrentValue(val)` 同步滑块视觉位置到钳制后的值（否则滑块拇指停在鼠标位置而 cfg 已被钳制）

**问题**：用户实测地形页 lo/hi 滑块能随意拖拽越过对方（lo > hi 或 hi < lo），没有实时约束。

**根因**：`TerrainConfigPanel.makeSlider` 的 `onChange` 回调只做了 `chart.updateControlPoint(slotIdx, isHi, v)`，没有对 `v` 做任何钳制。用户拖 lo 滑块时可以轻松超过当前 hi 值。

**修复**：
1. onChange 中读取 `slots.get(slotIdx).hiGetter/loGetter`，对 v 做实时钳制：lo 不能超过 hi、hi 不能低于 lo
2. 钳制后调用 `holder[0].setCurrentValue(v)` 同步滑块拇指视觉位置（避免值被钳住但拇指还在原处）
3. 用 `ParamSlider[] holder` 模式解决 lambda 引用未初始化变量的编译错误

**编译**：BUILD SUCCESSFUL ✅

## 重置按钮崩溃 + 跳页修复

**问题**：点击总重置键会崩溃（`FileSystemException: 文件被占用`），且重置后自动跳转到地形页。

**崩溃根因**：`resetToDefault()` 含 ~120 个 `cfg.set()` 调用。Forge 的 `AutosaveCommentedFileConfig.set()` 每次调用都触发 `save()` 写 TOML 文件。Windows 文件锁机制下，密集写入导致 `Files.newOutputStream` 抛出 `FileSystemException`。

**跳页根因**：`doReset()` 创建 `new GeoGenesisConfigScreen(parent)`，字段初始值 `tab = 0` 导致新屏幕始终打开地形页。

**修复**：
1. `doReset()` 中 `resetToDefault()` 包 `try-catch`，捕获 `WritingException` 不崩溃
2. 新增 `GeoGenesisConfigScreen(Screen parent, int tab)` 构造器，`doReset()` 传入 `this.tab`
3. `onClose()` 中 `new GeoGenesisConfigScreen(parent)` 改为 `new GeoGenesisConfigScreen(parent, tab)`

**编译**：BUILD SUCCESSFUL ✅
