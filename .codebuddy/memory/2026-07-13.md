## ⚠️ 致命坑：run/mods 里的 srg jar 导致整条 NoSuchFieldError 链（2026-07-13 复盘）

### 现象
- runClient 连续崩溃，错误全是 `java.lang.NoSuchFieldError: f_256783_` / `f_48171_` 等 srg 字段名，崩在 `Registries.*` / `Biomes.*` 引用处。

### 根因（关键！）
- `build.gradle` 的 `runs { mods { geogenesis { source sourceSets.main } } }` 已在 dev 运行时**从源码以 official 映射加载 mod**，运行时游戏也是 official 映射（`_mapped_official_`）。
- 但每步我都执行了 `build`（触发 `reobfJar`，把 mod 重映射成 **srg** 名）+ 把 reobf jar 拷进 `run/mods/`。
- Forge 加载 `run/mods/geogenesis-1.0.0.jar`（srg）时，其 vanilla 字段引用（srg 名）与 official 运行时游戏不匹配 → `NoSuchFieldError`。
- **之前所有"修复"（`ResourceKey` 强转、`RegisterEvent` 字符串比对、lazy coDec）都是围绕一个不存在的问题打转**，纯属浪费。

### 正确修复
1. **删除 `run/mods/geogenesis-1.0.0.jar`**（srg jar 是元凶）。
2. 代码还原为标准 Forge 写法：`DeferredRegister.create(Registries.CHUNK_GENERATOR/BIOME_SOURCE, MODID)` + `static final Codec CODEC = RecordCodecBuilder.create(...)`。这些在 official 运行时完全正常。
3. 只用 `gradlew runClient` / `runServer`（dev 走 sourceSets.main，official 映射），**绝不再把 reobf jar 拷进 run/mods**。

### 铁律（写进工程规范记忆）
- **dev 运行 = sourceSets.main（official 映射），不要往 run/mods 放任何 reobf jar。**
- `build`/`reobfJar` 只用于产出发布 jar；拷贝到 run/mods 只会污染 dev 运行环境。
- 遇 `f_XXXX_` / `m_XXXX_`（srg 名）`NoSuchFieldError/NoSuchMethodError` 时，第一反应是检查是否误把 reobf jar 放进了 run/mods，而不是改代码绕开 vanilla 字段。

## 2026-07-13 晚（接上）截图反馈 → 诊断 Ridge 噪声 + 双 smoother 是错的

### 用户反馈
1. 截图里红圈那条"曲线"是什么？（Ridge 噪声产生的"等高线"伪影）
2. 为什么用 ridge 噪声？山脊应该完全由侵蚀实现
3. 当前地形不符合 TERRAIN_TYPE_SCHEME.md / PLAN.md

### 根因
- **Ridge 算子**（`1 - |simplex|`）+ 幂次 `pow(., 1.5)` → 产生尖锐"等高线脊" → MC 整方块离散化后呈现"水平台阶+蜿蜒曲线"伪影（就是红圈）
- **我自己前后矛盾**：TERRAIN_TYPE_SCHEME.md §1 关键发现写"用 ridged 是错误范式"，PLAN.md R3 又写"脊线噪声成山脉"，R5 又写"水通道 = SimpleHydrology 雕山脊"——R3 和 R5 冲突，我选错了 R3
- **双 smoother 带宽不一致**：`landW` 用 `coastWidth` 当带宽，`coastFactor` 用 `coastWidth*2` 当带宽 → 在 c∈[0.50, 0.80] 区间两套曲线叠加 → 形成"非物理过渡带"
- **coastFactor 带宽太宽**：c=1.0 时 coastFactor 才到 0.83 → 内陆山被永远压制 17%

### 修复方案（待用户拍板）
1. LandShape：移除 `ridgeNoise` 节点 + 移除 belt 的高斯包络；belt 改用中频 FBM 滚动
2. LandShape：coastFactor 带宽从 `coastWidth*2` → `coastWidth*1.5`
3. CellGenerator：landW 带宽从 `coastWidth` → `coastWidth*1.5`（与 coastFactor 统一）
4. TerrainParams：`beltRidgePower` 标 @Deprecated，等阶段 2 Hydraulic 接入后删除
5. 阶段 2（RiverField + Hydraulic）才出真山脊——不靠 Ridge 噪声硬造

### 教训
- 设计文档内部不能有冲突条款（R3 vs R5 矛盾 → 我选错方向）
- "临时方案"不能引入"会污染视觉惯式的算子"（Ridge 一旦玩家看到就被当作设计意图）
- 多套 smoother 不能用不同带宽——会形成非物理的过渡带

## 创建世界崩溃修复：MapCodec.stable() 破坏 dispatch 叶子 codec 解码（2026-07-13 末）

### 现象
- 点「重新创建世界」崩溃：`Failed to parse geogenesis:worldgen/world_preset/geogenesis.json ... Missing overworld dimension`；根因 `Not a JSON object: null`。
- 良性 DIAG（`GeoGenesisClient.decodeWorldPresetDiag`）用裸 `JsonOps` 解码 generator 也报同样 `Not a JSON object: null`（误导，因裸 JsonOps 根本无法访问注册表）。

### 根因（读 MC 1.20.1 源码确认）
- `ChunkGenerator.CODEC = BuiltInRegistries.CHUNK_GENERATOR.byNameCodec().dispatchStable(ChunkGenerator::codec, Function.identity())`，即 `KeyDispatchCodec`（assumeMap=false）。
- `KeyDispatchCodec.decode`：要求被派发的叶子 codec `c instanceof MapCodecCodec`（走 `((MapCodecCodec)c).codec().decode(ops, input)` 直接解码对象）；否则走 `c.decode(ops, input.get("value"))`，而 world_preset JSON 无 `"value"` 包装 → `c.decode(ops, null)` → `getMap(null)` → **"Not a JSON object: null"** → overworld 维度条目被丢弃 → `WorldPreset.requireOverworld` 抛 "Missing overworld dimension"。
- `GeoGenesisBiomeSource.CODEC` 末尾 `.stable()` → `MapCodec.withLifecycle` 返回**非 `MapCodecCodec` 的匿名 MapCodec 子类**。`GeoGenesisGenerator.CODEC`（无 `.stable()`，是 `MapCodecCodec`）能正常解码，但在读取 `biome_source` 字段、经 `BiomeSource.CODEC` 派发到 `GeoGenesisBiomeSource.CODEC` 时崩。
- 仅 `GeoGenesisBiomeSource.CODEC` 带 `.stable()`，其余 `RecordCodecBuilder.create(...)` 都直接返回 `MapCodecCodec`。
