## 用户需求

玩家在游戏中观察到陆地地形类型占比异常、视觉上"都差不多、类型单一"，预期应有平原/丘陵/高原/山脉/山峰/雪峰等多种地形。经诊断与调研，根因不是单纯数值问题，而是**当前基础地形用"单一高度轴"建模**——`LandShape` 把各省"高度"做 softmax 凸组合，抹平了起伏信息；`classify` 用单一 `eLand` 阈值分级，且 `SNOW` 用纯海拔+造山带阈值而 `Cell.isSnow` 从未赋值（文档要求的"海拔×温度×纬度雪线覆盖层"未实现）；同时 `geogenesis-common.toml` 振幅是旧低值，覆盖了新的 builder 默认值。

用户要求：不只要调数值，而应按**地理学**做**更好的**侵蚀前基础地形（参考旧文档但超越它），并参考联网调研结论（构造抬升建模、海拔×起伏二维矩阵、参数化地质类型）。

## 产品概述

重构"侵蚀前基础地形"生成范式：地形类型由**地质省特征（海拔基面 + 起伏幅度 + 细节噪声）连续合成**，而非混合单一高度。地形分类从"单一高度轴"升级为**海拔(elevation) × 起伏(relief) 二维矩阵**，并新增**海拔×温度×纬度耦合的雪线覆盖层**。使平原/丘陵/高原/山脉/峰按真实地理关系自然涌现、平滑过渡，且雪线随气候变化。

## 核心特性

- **双场合成**：`LandShape` 从"混合高度"改为产出 `elevation`（各省特征海拔基面 softmax 混合）与 `relief`（各省特征起伏幅度 × 细节噪声 softmax 混合）两场；`eLand = elevation + relief` 作为侵蚀前基础高度。
- **海拔×起伏二维分类**：`classify` 按"高/低海拔 × 平/崎岖"判定 —— 高且崎岖=山脉/峰、高且平=高原、低且崎岖=丘陵、低且平=平原、盆地省主导且低洼=盆地；山脉与高原靠 relief 在同海拔区分，彻底摆脱单一高度轴。
- **气候耦合雪线覆盖层**：新增 `applySnowLine`，由海拔 × 温度（温度含纬度）写入 `Cell.isSnow`，`BiomeClassifier` 改用 `isSnow` 判雪。
- **配置修复与扩展**：同步 toml 过期振幅到 builder 高值；新增每省 relief 振幅配置项（六处同步铁律）；适度 sharpen 省权重使各省区域更分明。
- **验证**：`runPreview` 地形类型图层目检 12 类分布；`runClient` 飞行目检多样性与雪线随纬度变化。

## 实现思路

把"侵蚀前基础地形"从单一的连续高度场，重构为**地质省特征连续合成**的两场模型，遵循调研结论：

1. **建模地质特征而非最终海拔**（对齐 Tectonic Uplift 论文"model uplift, not elevation"）：每省 `i∈{craton,belt,plateau,basin}` 产出两个独立量——特征海拔基面 `baseEᵢ`（沿用现有过程形态区间）与特征起伏幅度 `reliefAmpᵢ`（新增常量/配置，craton 中低 ~0.12、belt 高 ~0.30、plateau 极低 ~0.03、basin 低 ~0.05，即 danbgray 的 variation），并各带细节 FBM 噪声 `detailᵢ(x,z)∈[-1,1]`（新增每省高频噪声或复用现有 beltHigh/platMid 等）。
2. **softmax 混合"特征"而非"高度"**（否定当前抹平 relief 的凸组合高度）：`elevation = Σ wᵢ·baseEᵢ`，`relief = Σ wᵢ·(reliefAmpᵢ·detailᵢ)`，`eLand = elevation + relief`。这样在 belt 省区域自然得到"高海拔+高起伏"，在 plateau 省区域得到"高海拔+低起伏"，craton 区域得到"低海拔+中低起伏"，起伏信息不再被平均掉。
3. **保持既有海陆统一加法模型**：`e = eOcean + eLand`，海岸线由 `e` 场自然过零涌现（符合 terrain-rebuild §1.4），不引入硬边界。
4. **海拔×起伏二维分类**（`classify`）：高/低海拔 × 平/崎岖 矩阵，山脉与高原靠 relief 在同海拔区分，平原与丘陵靠 relief 在低海拔区分；PEAK 作为 MOUNTAINS 子型（仅山脉且 `elev>PEAK_E`）；盆地由省权重主导且低洼判定。
5. **气候耦合雪线覆盖层**（`applySnowLine`）：`effSnow = seaLevel + (snowLineTop - seaLevel)·(0.5 - 0.5·temperature)`，寒带雪线低、热带雪线高；`Cell.isSnow = isLand && height >= effSnow`。温度已含纬度信息（`CellGenerator.sample` 用 `tempLatitudeScale` 由世界 Z 算温度）。

关键决策：

- 不恢复植被装饰（`applyBiomeDecoration` 空操作保留，后续项）。
- 不重写 `BiomeClassifier` 为完整 5×5 温湿表 / 海拔递减率 / 雨影（文档 §4.7/§4.7.1 深化，记后续），本次仅把雪判据从 `isCold()` 改为 `isSnow` 覆盖层。
- 不接线 `mountainCap`：`e` 已 `clamp(e,-1,1)`，`beltPeak=0.95` → Y≈307 < 320，不超界。
- classify 候选常量（`ELEV_HIGH/RELIEF_HIGH/PEAK_E` 等）先作 `LandShape`/`CellGenerator` 内命名常量，目视验证后再考虑升配置。

## 实施备注

- **六处同步铁律**：现有 land 振幅 + 省权重 + 新增 relief 4 项，须同步 `GeoGenesisConfig`(BUILDER 默认；确认 `GeoGenesisConfigScreen.buildParams` 无独立硬编码副本，否则一并同步) + `TerrainParams.defaults()` + `geogenesis-common.toml` 三处数值一致；预览 `defaultParams()` 读 builder 默认，自动一致。
- **性能**：`LandShape.sample` 每格新增 4 次细节噪声 `compute`（与现有 4 次省权重噪声同量级），仍为常数级 O(1)/格；`relief` 组合为简单算术，地形产线复杂度不变。
- **回归控制**：`OCEAN/DEEP_OCEAN/BEACH` 前置判定与 `e<0` 判洋逻辑不动；海岸线仍由 `e` 自然过零涌现；`eLand` 为连续场，各省 softmax 权重连续 → 地形类型平滑过渡，无硬边、无 tile 接缝；`height` 映射不变，方块填充链路不受影响。
- **日志**：不改日志；辅助标定时可在 `classify` 临时打 histogram 统计各 `TerrainClass` 占比，确认后删除（不进最终提交）。
- **旧文档**：`docs/01-架构设计/03-地形类型方案-terrain-type-scheme.md` 已过时，本次新设计落地后建议另写/更新设计文档并补索引（用户规则：docs 新文档需更新索引）。

## 架构设计

侵蚀前基础地形由"地质省特征"连续合成两场（海拔 + 起伏），分类与雪线解耦：

```mermaid
flowchart LR
  TOML[geogenesis-common.toml] --> SPEC[ForgeConfigSpec BUILDER 默认]
  SPEC --> BP[buildParams / defaultParams]
  BP --> TP[TerrainParams 含 relief 振幅]
  TP --> LS[LandShape: provinceWeights + 每省 baseE/reliefAmp/detail]
  LS -->|elevation, relief| CG[CellGenerator.sample]
  CG -->|eLand=elevation+relief| E[e=eOcean+eLand]
  CG --> CL[classify: 海拔×起伏 矩阵 -> TerrainClass]
  CG --> SN[applySnowLine: 海拔×温度 -> isSnow]
  CL --> BC[BiomeClassifier: switch(terrainType) + isSnow 覆盖]
  E --> GEN[GeoGenesisGenerator.fillFromNoise]
```

修改集中在 `LandShape`（双场产出）、`CellGenerator`（装配+分类+雪线）、配置三处与 `BiomeClassifier`（雪覆盖层），不改变节点结构与数据流方向。

## 关键代码结构（核心改动）

`LandShape.sample` 双场产出（示意，命名常量待目视微调）：

```java
// 每省特征：baseEᵢ（海拔基面）与 reliefAmpᵢ（起伏幅度，新增配置）；detailᵢ(x,z) 细节 FBM∈[-1,1]
double elevation = 0, relief = 0;
for (int i = 0; i < 4; i++) {
    elevation += w[i] * baseE[i];
    relief    += w[i] * (reliefAmp[i] * detail[i].compute(wx, wz));
}
// 返回 elevation 与 relief（CellGenerator 求和得 eLand）
```

`CellGenerator.classify` 海拔×起伏矩阵（示意）：

```java
// 前置: e<0 -> OCEAN/DEEP_OCEAN; 0<e<0.03 -> BEACH（不变）
boolean high   = elevation > ELEV_HIGH;   // 候选 0.45
boolean rugged = Math.abs(relief) > RELIEF_HIGH; // 候选 0.10
if (wBasin > 0.40 && elevation < 0.08) return BASIN;
if (high && rugged)  return (elevation > PEAK_E) ? PEAK : MOUNTAINS; // PEAK=山脉子型
if (high && !rugged) return PLATEAU;
if (!high && rugged) return HILLS;
return PLAIN;
```
