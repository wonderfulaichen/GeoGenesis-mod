## 用户需求

在已落地的「迭代式 SimpleHydrology」侵蚀引擎基础上，按你确认的两项死线收尾：单 region 首次计算硬上限 ≤1s（质量优先），region 尺寸固定 512。河流须是 360°自由、侵蚀=河流同一套物理、迭代自组织出蜿蜒且连通的水系，消除平行沟壑与碎片化水塘。

## 核心特征

- 已核实（代码已落地）：`HydraulicErosion` 已实现持久 `flowX/flowY` 方向场 + 重力下坡加速 + 沿既有流向的动量正反馈（夹角对齐才强化）+ 长寿命水滴（160/240 步）+ 世界对齐撒滴（`rngState=hash(ox,oz)`），`carveRivers` 阈值 0.06 / 半径 3。即「迭代自组织河网」方向已就位，非 D8。
- 待修：运行期 Forge 配置 `RIVER_MIN_DISCHARGE` 默认仍为 12.0（独立预览 `RiverSettings` 已是 4.0），导致游戏内河流阈值过高、河网稀疏不连通，抵消了 `carveRivers` 放宽的效果。
- 待加：单 region 首次计算的 1s 硬预算 + 超预算自动降级（砍水滴），保障极端区域不卡顿、破死线前先降质量。

## 功能与视觉效果

- 游戏内与独立预览中，河流连成蜿蜒树状水系，平行直线沟壑消失，碎片水塘消失。
- 任一 region 首算 ≤1s（之后走 `TileCache` LRU 缓存无感）；极慢区域超预算时自动减少水滴数，保流畅不崩溃。

## 技术栈

- Java 17 + Minecraft Forge 1.20.1 模组（Gradle，`gradlew.bat compileJava` / `runClient` / `runPreview`）。
- 零 MC 依赖核心：`HydraulicErosion`（droplet 侵蚀 + 河谷刻蚀）、`RiverField`（region 级装配）、`RiverSettings`（参数）；运行期读数来自 `GeoGenesisConfig`。

## 现状核实（已读源码确认）

- `HydraulicErosion.java` 已是目标形态：L55-56 分配持久 `flowX/flowY`；L138-156 重力 + 动量正反馈模型正确（对齐 `water.h`）；`LIFE_LARGE=160/LIFE_FINE=240`；`carveRivers` 阈值 0.06（L229）、半径 3（L218）。**无需重写**。
- `RiverField.java` 已正确调用 `erosion.apply(...)`（L96），`gsz=size+2*PAD`，region 尺寸由调用方传入（保持 512）。
- `RiverSettings.defaults()` 的 `riverMinDischarge` 已是 4.0（L32）；但 `GeoGenesisConfig.RIVER_MIN_DISCHARGE` 默认仍为 12.0（L327），且 `gd()` 回退值取 `RiverSettings` 的 4.0（L542）——无外部配置文件时游戏内实际用 12.0，需对齐。

## 实现方案

### A. 配置默认值对齐（GeoGenesisConfig）

- `RIVER_MIN_DISCHARGE` 默认 `12.0` → `4.0`（与 `RiverSettings`/预览一致，使中等流量段也标河、铺水连通）；下限由 `1.0` 放宽到 `0.5`（便于调参，4.0 仍在范围内）。
- 其余（`erosionStrength=1.0/erosionDropsMul=1.5/erosionErodeMul=1.2/riverValleyDepth=0.06`）已与 `RiverSettings` 一致，不改动，避免回归。

### B. 单 region 1s 硬预算 + 自动降级（HydraulicErosion.apply）

- 新增常量 `COMPUTE_BUDGET_NS = 1_000_000_000L`（注释标注为你确认的死线）。
- `apply` 进入水滴循环前取 `startNs = System.nanoTime()`；在 `largeDrops`/`fineDrops` 两个循环中每 1024 滴检查一次 `System.nanoTime()-startNs > COMPUTE_BUDGET_NS`，超过则置 `overBudget` 并跳出水滴循环（不再生成新水滴）。
- 降级仅减少水滴数（后续 `carveRivers`/`smoothErosionResult` 仍全量跑，开销可忽略），结果更稀疏但耗时恒定在死线内；正常区域远低于 1s，降级为罕见安全网，确定性基本保留。
- 不改动任何方法签名与坐标约定；`RiverField` 调用方与 region 512 尺寸不变。

## 性能与可靠性

- 成本模型（region 512 → `gsz=544`，`interior≈528`，`area≈278k`）：`largeDrops≈area*0.015*1.5≈6.3k`、`fineDrops≈area*0.030*1.5≈12.5k`，平均寿命 ~200，核 ~80 点 → 约 3 亿次浮点操作 ≈ 数百毫秒，远低于 1s；降级仅作极端兜底。
- 确定性：`rngState=hash(ox,oz)` 保证同机同 seed 同结果；降级路径依赖墙钟，正常不触发，可接受（你优先「不卡顿」）。
- 风险：无跨区污染（`erosion` 每 region 新建）；近海平面 `smoothErosionResult` 已抑制过深沟壑，保留。
