# 2026-06-03 噪声优化与开源项目调研

## 一、开源项目调研

### 1. RTG (Realistic Terrain Generation)

| 维度 | 详情 |
|------|------|
| 仓库 | https://github.com/Team-RTG/Realistic-Terrain-Generation |
| 语言/平台 | Java / Minecraft 1.12.2 Forge |
| 规模 | 3402 commits，97 releases |
| 噪声引擎 | KdotJPG 的 **OpenSimplex Noise**（比 Perlin 快，方向性伪影更少） |
| 许可证 | GPL-3.0 |

**核心架构发现：ChunkInfo 噪声缓存模式**

RTG 的 commit 记录中明确写道：

> "A ChunkInfo object is passed around in chunk generation to avert the need for repeated noise calls."

这正是 GeoGenesis 当前噪声瓶颈的解决方案。GeoGenesis 的 `computeHeight` 每像素调用 `sampleContinentRaw` + `sampleTerrainBase`，内部各自独立调用 `domainWarp` + FBM 链，导致同一像素的 domainWarp 被重复计算多次。

**RTG 噪声架构特点：**
- `SimplexNoise` 接口定义了 `multiEval2D()` 批量评估方法，一次调用评估多个噪声类型
- 噪声模块独立于世界生成（`rtg/api/util/noise/` 包）
- 使用 OpenSimplexNoise 而非 Perlin，O(n²) 复杂度 vs O(2^n)

## 二、GeoGenesis 当前噪声开销分析

### 2.1 噪声实例

`NoiseEngine` 构造函数中创建了 **15 个独立 ImprovedNoise 实例**：

```java
climateNoise, moistureNoise, continentNoise,
warpLargeNoise, warpMediumNoise,
fractalLarge, fractalMedium, fractalSmall,
valleyLarge, valleySmall,
ridgeNoise, ridgeNoise2,
detailNoise, riverNoise, yOffsetNoise
```

每个实例有独立的 seed 和 permutation table（256×2=512 ints），内存开销不大但调用分散不利于缓存。

### 2.2 domainWarp 重复计算

`domainWarp(float x, float z, float strength)` 被多处独立调用：

| 调用者 | strength | 调用频率 |
|--------|----------|---------|
| sampleFractalLarge | 60f | 每次 |
| sampleFractalMedium | 30f | 每次 |
| sampleTerrainBase | 80f | 每次 |
| sampleValleyLarge | 20f | 每次 |
| sampleRidge | 35f | 每次 |
| sampleCellNoise | 30f | 每次 |
| sampleTemperature | 800f (手动) | 每次 |

**核心问题**：不同 strength 的 warp 结果无法直接共享，但同一像素的同一 strength 被多次调用时可以复用。

### 2.3 computeHeight 调用链

```
computeHeight(worldX, worldZ)
  ├── sampleContinentRaw()     → 3层 domainWarp (6次 noise) + 3+3 oct FBM (6次)
  └── sampleTerrainBase()      → domainWarp(80f) (4次 noise) + 2+1 oct采样 (3次)
```

仅这两个函数约 **19 次 noise 调用/像素**。加上后续各层 erosion 相关采样，总计约 **120 次/像素**。

在 112×112 tile 中 = 12,544 × 120 ≈ **150 万次 noise 调用**。

## 三、优化方案

### 方案 A：TileNoiseCache — domainWarp 预计算复用（最大收益，推荐先做）

**思路**：借鉴 RTG 的 ChunkInfo 模式，在 `generateErosionTile` 的 112×112 循环中，为每个像素预计算所有需要的 domainWarp 结果，存入缓存，然后传递给所有需要它的采样函数。

**关键设计**：
- 在 tile 级别预计算不同 strength 的 domainWarp 偏移
- 也预计算 continent 的 3 层 warp
- 采样函数改为接受预计算的 warp 坐标而非原始坐标

**预估收益**：噪声调用减少 50-60%

### 方案 B：合并弱相关的噪声采样（中等收益）

**思路**：`sampleTerrainBase` 的 `sampleOctaveNoise` 和 `sampleFBM` 可以合并为一个批量调用，减少 `getYOffset` 的重复计算（`getYOffset` 内部也有 3 次 noise 调用）。

**预估收益**：10-15%

### 方案 C：降低非关键 octaves（最小改动）

**思路**：
- `sampleFractalLarge` 的 FBM 从 4 octaves 降到 3
- `sampleValleyLarge` 的 FBM 从 2 降到 1
- `sampleErosionNoise` 的 3 层 FBM 合并为 2 层

**预估收益**：15-20%

**风险**：需验证地形质量不下降

## 五、实施记录

### 2026-06-03 实施

#### 方案 C：降低 octaves（已实施，编译通过）

| 函数 | 旧 octaves | 新 octaves | 每像素减少 noise 调用 |
|------|-----------|-----------|---------------------|
| sampleFractalLarge | 4 | 3 | -1 (主 noise) + -1 (getYOffset×3) = **-4** |
| sampleFractalSmall | 4 | 3 | **-4** |
| sampleRidge | 5 | 4 | **-4** |
| sampleTerrainHills | 4 | 3 | **-4** |
| sampleElevation | 4 | 3 | **-4** |

**总减少**：5 个函数 × 4 次 noise/octave = 约 **20 次 noise 调用/像素**

#### 方案 A：continent 缓存（已实施，编译通过）

- `TerrainCache` 新增 `continentCache`（ConcurrentHashMap）
- `generateErosionTile` 中预计算 `continentRaw` 并缓存到 chunk 级别
- `compute` 中从缓存读取 continent，避免重复 `sampleContinentRaw`
- **收益**：每个 chunk 的 `compute` 中节省 16×16=256 次 `sampleContinentRaw` 调用（每次 ~12 次 noise = 约 3072 次 noise/chunk）

- 对比优化前后的地形视觉效果

## 六、后续实施记录（2026-06-03 下午）

### Bug 修复

#### Bug 1：河流未完全关闭
- `HydrologySystem.riverEnabled` 默认为 `true`，`setRiverEnabled(false)` 被注释掉
- 导致 `RiverBrushSystem` 仍在运行，每个群系查询都执行昂贵的噪声计算
- 修复：取消注释 `hydrologySystem.setRiverEnabled(false)`

#### Bug 2：侵蚀种子依赖 tile 原点
- `ErosionEngine` 中 3 处 `Random(ox * 31L + oz * 73L)` 导致相邻 tile 侵蚀不一致 → 地形断裂
- 修复：改为 `Random(worldSeed)`，所有 tile 共享同一随机序列

#### Bug 3：tile 居中对齐错误
- `Math.round(2/3) = 1` 导致 chunkX=2 映射到错误 tile 中心
- 修复：改为 `Math.floorDiv(chunkX, 3) * 3`

### 架构发现

- **TerrainCache 是死代码**：没有被实例化，实际地形生成走 `fillFromNoise` 内联管线
- 之前对 TerrainCache 的 continent 缓存修改虽然编译通过但不执行

### 新功能

#### 双层侵蚀（大沟壑 + 小细节）
- 第一层（大尺度）：r=6, 惯性=0.35, 80粒子/chunk, 寿命50, 蒸发=0.12, 沉积=0.6
- 第二层（细节）：r=4, 惯性=0.05, 280粒子/chunk, 寿命30, 蒸发=0.01, 沉积=0.3
- 先大后小：大尺度先形成骨架，细节层在此基础上添加纹理

#### 火山地形
- 借鉴 TerraForged VolcanoPopulator
- cellular noise 散布火山中心点（scale=800, density=0.15）
- 锥形高度：外坡 alpha² 曲线 + 火山口凹陷（inversionPoint=0.85）
- 只在陆地+高relief区域生成

#### plateSystem 缓存
- `computeHeightWithPlate` 方法接受预计算的 PlateData
- `fillFromNoise` 中预计算 plateCache，避免重复调用
