# 侵蚀模拟优化实验记录 — 2026-06-01

## 实验目标
在保持 F1 ≥ 0.725 的前提下，优化河流侵蚀模拟的性能，同时防止中游断流（≥50px）。

---

## 核心发现：Cascade 间隔调用

| 指标 | 数值 |
|------|------|
| `cascade()` 计算占比 | ~50-60% / 步 |
| 间隔步数 | 每 3 步调用一次 |
| F1 变化 | 0.772 → 0.750（仅降 0.022） |
| 性能提升 | ~40% |
| 断流情况 | 无显著恶化 |

**结论**：这是目前最简单、最安全、效果最好的优化方案。

---

## 证伪的三个方案

### 1. Jacobi 批量侵蚀 ❌

**思路**：先计算所有粒子的地形变化但不修改地形，最后统一应用侵蚀。

**失败原因**：缺少自组织反馈（self-organizing feedback），河流无法自然形成河道。

| 指标 | 结果 |
|------|------|
| F1 分数 | 0.339 - 0.350 |
| 对比基准 | 0.772（Gauss-Seidel） |
| 结论 | 不可行 |

**教训**：侵蚀模拟必须依赖即时反馈，批量处理破坏了地形演化的连续性。

---

### 2. 减少迭代 + Stream Power 后处理 ❌

**思路**：减少粒子迭代次数，用 Stream Power Law 公式后处理补充侵蚀。

**失败原因**：Stream Power Law 只能增强已有河道，无法创造新河道。

| 指标 | 结果 |
|------|------|
| F1 下降 | 0.07 - 0.1 |
| 断流情况 | 恶化 |
| 结论 | 不可行 |

**教训**：后处理公式不能替代粒子模拟的物理过程。

---

### 3. 模组逐区块日志计时 ❌

**思路**：在模组运行时对每个区块的侵蚀步骤进行详细日志计时。

**失败原因**：I/O 阻塞导致世界加载卡死。

| 指标 | 结果 |
|------|------|
| 性能影响 | 严重阻塞 |
| 可用性 | 无法正常运行 |
| 结论 | 不可行 |

**教训**：性能分析工具本身不能成为性能瓶颈。

| # | 教训 |
