## 后续优化优先级（只分析，尚未实施）

1. **输入采样重用**：ParticleTile 每 tile 146×146=21316 次 B 采样，相邻 owner 步长 48，输入窗口大量重叠。先量同坐标重算、缓存命中/碰撞和同 owner 重建，再评估按上下文绑定的有界分块 B 缓存；保持原 double 运算与 float 转换。
2. **任务服务能力 / 调度**：当前 CellGenerator 使用 Budget(4,512,1024)。测实际活跃线程、CPU 与内存，再做受控并发对照。不能只扩大队列（不提升服务能力），也不能因队列长便无限加线程。核查内核的 commonPool 并行与 tile 工作池叠加。
3. **水文窗口批量精确采样**：outlets 仍占管线约 95.8%。WindowOutlets 每窗口 126017 次高度查询，每次 requestExact/await/assemble；评估同上下文共享纯高度缓存或有界批量求值，保留精确 P、边界与确定性。先量点缓存命中，不能把理论几何重叠比例当实际节省比例。
4. **次要项**：方块铺设、装饰、洞穴均非当前首要启动长尾。发布 gate / 生命周期锁本轮证据很小，不优先再次重构。

### 正确性边界

- 禁止把原子 Entry 缓存退回三条独立 AtomicLongArray（之前已实测键值撕裂）；省分配必须另有完整一致性协议及负控。
- 不减粒子、不改侵蚀几何、不直接以 B 代替结构/群系的 P 输入。
- BiomeColumnCache 既有命中返回 surface、miss 才做 cave override 的行为使缓存策略与可观察输出耦合；不能把扩容/换哈希当无语义风险的普通 memo 优化。
- 后续每项实现先方案；要求独立冷 JVM 对拍、并发一致性与生命周期探针、常用种子实机复测。当前记录不是算法效果已全面验收的声明。
