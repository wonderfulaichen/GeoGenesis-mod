## 一、参考项目到底做了什么

### 1.1 一句话

玩家在配置屏点「完成」→ **不出现原版"正在准备创建世界"的灰色屏幕**，
而是接着沙盘那张图往下推：正交画面 morph 成透视、镜头飞到落点上空、
区块陆续到位后**沙盘柱子一块块消散、露出下面真实的 MC 地形**、
最后镜头顺着一条航线落进玩家眼睛。

### 1.2 六个阶段

| # | 阶段 | 时长 | 做什么 |
|---|---|---|---|
| 1 | **开场（正交→透视）** | 3000ms | 正交画面按 progress 混合到透视投影；FOV 15→40；地形从"压缩"展开成真实高度 |
| 2 | **换源** | 中途一帧 | 粗场（1格16方块）换细场（1格4方块）。两份场共用同一份区块采样 ⇒ 换的那帧不差一个像素 |
| 3 | **空中等待** | 视情况 | 镜头在空中极缓单向绕（1.5°/秒，最多 18°）；等真实区块数据到货 |
| 4 | **柱子让位** | 每块 1600ms | 从落点中心向外扩；每块等"它身下的真实区块真的进了 Sodium 绘制列表"才开始淡出 |
| 5 | **收尾消散** | 300ms | 剩下没轮到的柱子一起散干净（镜头此时不动） |
| 6 | **落机** | 3400~5500ms | 四段航线：空中 → 大门上方 → 门廊外 → 顺门洞进屋 → 玩家眼睛。竖直下降列落在门廊外，不刮檐口 |

### 1.3 关键设计决策（每条都有血泪注释）

| 决策 | 原因（参考项目原文摘录） |
|---|---|
| **柱子原地淡、不挪柱顶** | 「以前那一滑看着就是'柱子往上长一边散掉'，像往上飘」 |
| **等真实网格进绘制列表才淡** | 「不会出现'柱子化了、底下还是空的'」 |
| **让位从落点中心向外扩** | 「按区块到货先后淡会从某条边推向另一边」 |
| **只等视距内的等待圈** | 「细场 961 个区块列，视距 12 只加载得到 625 块，外面永远等不到 ⇒ 以前吊在天下十几秒」 |
| **视距外按各自上限放行** | 「不这样收尾就会把几百根柱子吊到最后一起抹掉 → 唰地一起消失」 |
| **动画时钟单帧封顶** | 「建世界那几秒渲染线程会被堵住半秒到一秒多 ⇒ 不让追镜头会停住再启动；按 120ms 追只小跳一下」 |
| **动画期间玩家无敌 + 隐藏 HUD + 静音** | 「免得受伤红屏和镜头抖打断镜头运动」 |
| **长焦（AERIAL_FOV=40）** | 「窄视野下同样俯角盖得住的距离远得多，镜头不用俯到接近顶视」 |

### 1.4 依赖的外部机制

| 依赖 | 作用 | 我们有吗 |
|---|---|---|
| `MinecraftSiteLoadMixin` | 把原版 `LevelLoadingScreen` 换成 `SiteRevealScreen` | ❌ 需新建 |
| `SiteRevealGuard` | 拦住原版"收区块过渡屏" | ❌ 需新建 |
| `ChunkRenderListMixin`（Sodium） | 探测"某区块真的进绘制列表" | ❌ 需新建（可选） |
| `CameraMixin` / `GameRendererMixin` | 每帧接管相机与 FOV | ❌ 需新建 |
| `SiteRevealState` | 服务端→客户端的落点交接 | ⚠️ 我们已有类似（`SpawnSelection`） |
| `RevealCinematics.setAerial` | 天象让路（云/日月） | ❌ 需新建 |

## 二、我们的现状与差距

### 2.1 已有

| 能力 | 现状 |
|---|---|
| 沙盘渲染器 | `SandboxRenderer` + `SandboxGeometry`（正交投影，GUI 批） |
| 出生点交接 | `SpawnSelection` + `SpawnPositionHandler`（v35 刚做） |
| 数据层 | `CellCache` → `TerrainFieldData`（方块级精度） |
| 切换/相机动画 | v35 已做（`transition` + `zoomBoost` + `orbit`） |

### 2.2 缺什么

| # | 缺口 | 工作量 |
|---|---|---|
| 1 | **透视投影** —— 现在只有正交 3×3 旋转。落成动画需要 `Vec3 eye/look/right/up` + 透视投影矩阵 | 中 |
| 2 | **换屏时机** —— 需要 mixin 拦 `LevelLoadingScreen` | 小（但需要 mixin 基础设施） |
| 3 | **真实区块到位探测** —— 参考项目靠 Sodium mixin | 中（可先退化） |
| 4 | **相机接管** —— 每帧改 `Camera`/`GameRenderer.fov` | 小~中 |
| 5 | **落机航线** —— Hermite 插值 + 站立点检测 | 中 |
| 6 | **柱子让位调度** —— 按距离排波次 + 逐块淡出 | 中 |
| 7 | **换源（粗场→细场）** | 我们只有一份数据 ⇒ **不需要** |

## 三、我方方案（分三步交付，每步可独立验收）

### 步骤 A：最小可用落成动画（主体，建议先做）

**目标**：点「完成」后不再看到灰色加载屏，而是看到沙盘 → 真实世界的平滑过渡。

| 项 | 做法 |
|---|---|
| **触发** | `MinecraftSiteLoadMixin`：`doWorldLoad` 里把 `LevelLoadingScreen` 换成我们的 `RevealScreen`；只在"从配置屏进来 + 有选点"时生效 |
| **开场** | 复用现有 `SandboxRasterizer` 的正交画面，按 progress 从**正交混合到透视**。透视侧新增 `PerspectiveCamera`（eye/look/right/up + fov） |
| **镜头** | 空中机位：落点上空 110 格、俯角 30~45°（`solveAerialPitch` 自动挑）、FOV 40；极缓单向绕 1.5°/s |
| **让位** | **不用 Sodium mixin**，退化为参考项目的 `NO_FILTER_MESH_MS` 模式：区块数据到货（`clientChunkCache.getChunk` 非空且非空壳）+ 1200ms 余量 ⇒ 开始淡。每块 1600ms 五次曲线，原地淡、柱顶不动 |
| **收尾** | 等待圈（视距 clamp 到 8~12）内全部放行后，剩下一把散掉 300ms，然后落机 |
| **落机** | 简化版：空中 → 落点上空 14 格 → 玩家眼睛，两段 Hermite；不搞"大门/门廊"（我们没建筑） |
| **动画时钟** | 单帧封顶 80ms，卡帧不瞬移 |
| **副作用处理** | 动画期间：隐藏 HUD、玩家无敌、手不渲染；结束全部恢复 |

**不做**（本轮）：Sodium 绘制列表探测、换源、蓝图线框、门廊航线。

### 步骤 B：接 Sodium 绘制列表（可选增强）

装 Sodium 时用 `ChunkRenderListMixin` 探测"某区块真的进绘制列表"，
让柱子让位更精准（不会出现"柱子化了、底下还是空的"）。
没装 Sodium 自动退化为步骤 A 的行为。

### 步骤 C：打磨（可选）

- 蓝图线框（如果日后有建筑）
- 天象让路（云/日月）
- 落机音效

## 四、风险与对策

| 风险 | 说明 | 对策 |
|---|---|---|
| **mixin 崩溃风险** | 拦 `LevelLoadingScreen` 需 mixin，写错会崩游戏 | 严格 `@Inject` + `cancellable`，异常时捕获并退回原版；先只在小范围测试 |
| **等待时间不可控** | 区块加载慢时镜头要在空中等 | 三层上限：等待圈 12 区块 / 总 25s / 硬上限 60s |
| **与出生点接管的时序** | 落成动画需要落点，而落点在 `CreateSpawnPosition` 才确定 | 用 `SpawnSelection` 的 Pending 先播（点哪就是哪），服务端确定后如有偏差再 retarget |
| **数据不完整** | 我们只采了平面窗口那一片 | 动画前把等待圈内区块全部入队采完；圈外直接按上限放行 |
| **性能** | 每帧要画几百个柱子 + 真世界 | 参考项目实测本帧开销可接受；我们柱子数更少 |

## 五、需要你先定的三个问题

1. **步骤 A 的范围是否合适？**
   （我建议：先做 A，不做 Sodium 探测/换源/蓝图。理由是这三项依赖我们没有的东西，
   且不做也不影响"能看到落成动画"这个核心体验。）

2. **落机航线**：我们没建筑，参考项目那套"大门/门廊"用不上。
   我建议简化为「空中 → 落点上空 14 格 → 玩家眼睛」。
   你想要更花哨的（比如绕落点转一圈再落）吗？

3. **失败兜底**：如果动画过程中出任何异常，是
   (a) 安静退回原版加载屏，还是
   (b) 直接跳过动画进世界？
   我建议 (a) —— 玩家至少能看到正常的加载画面。
