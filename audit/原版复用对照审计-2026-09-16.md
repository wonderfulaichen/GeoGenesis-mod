## 0. 判定方法（判据本身，务必先读）

自定义 `ChunkGenerator` 里，「原版是否已经在生成某物」有一个**决定性判据**：

```
GeoGenesisGenerator.applyBiomeDecoration  →  super.applyBiomeDecoration（原版实现）
⇒ 只要该特征在该群系的 BiomeGenerationSettings 里，它就【一定在生成】
```

`BiomeGenerationSettings.features()` 按 `GenerationStep.Decoration` 11 步索引。
因此查证路径固定为：**读原版 datapack 的 `worldgen/biome/<biome>.json` 的 `features[]` 数组**。

1.20.1 的 datapack 可从本地 client jar 直接读：

```
D:\.gradle\caches\forge_gradle\minecraft_user_repo\mcp\1.20.1-20230612.114412\
    joined\downloadClient\client.jar  →  data/minecraft/worldgen/biome/*.json
```

> ⚠ 踩坑（本会话踩过两次）：`D:\.gradle\caches\ng_execute\*` 下**同时缓存多个 MC 版本**的解压产物。
> 出现 `pale_garden.json` / `cherry_grove.json` 的目录是 **1.21.4**，不是 1.20.1。
> 认版本的锚点：1.20.1 的 `BiomeGenerationSettings` 是 `Map<GenerationStep.Carving, HolderSet<...>>`
> + `getCarvers(Carving)` 带参；1.21 是 `getCarvers()` 无参 + 单 `HolderSet`。

### B-1 ★ 已核（2026-09-16）：`disk_*` 与 `underwater_magma` 会和我们的河湖产状冲突吗？

**结论：不冲突**（`disk_*` 在本世界里近乎**惰性**）。证据 = 从 1.20.1 `client.jar` 读出的
`placed_feature` / `configured_feature` 原始 JSON：

| 特征 | 放置条件（实测配置） | 在本世界的行为 |
|---|---|---|
| `disk_sand`(count **3**) / `disk_clay`(1) / `disk_gravel`(1) | `heightmap = OCEAN_FLOOR_WG` + **`block_predicate_filter: matching_fluids = water`**；**`target = [dirt, grass_block]`** | **近乎惰性**：水下的**替换目标被限死为 `dirt`/`grass_block`**，而本项目的河/湖/海底是 `sand`/`gravel`/`stone`（`fillFromNoise` 直接铺）⇒ 磁盘特征**找不到目标** ⇒ 基本不生效。只可能出现在**水边的草/土处**（沼泽岸等）⇒ 与原生观感一致，无破坏 |
| `underwater_magma` | `count 44~52` + `height_range 0..256` + **`surface_relative_threshold_filter(OCEAN_FLOOR_WG, max_inclusive = -2)`** ⇒ **只采样"水体底面以下 ≥2 格"**；config `floor_search_range=5` / `probability=0.5` / `radius=1` | **范围被限死在水体之下**：只会在**海/湖底以下**的岩层里零星塞入岩浆块（量小：须在 5 格内找到底面且过 0.5 概率）⇒ **不触及陆地、不影响河面**；与原生海洋一致，**保留** |

> **为什么这两个不用像 §A 的"岩块团块"那样过滤**：判据是**替换目标**。
> 岩块团块的目标是 `STONE_ORE_REPLACEABLES`（含 stone/granite/andesite）⇒ **正面命中本地层**；
> 而 `disk_*` 的目标是 `dirt`/`grass_block`、`underwater_magma` 被限在水体之下 ⇒
> **够不到岩层主体**。⇒ **不需要动它们**。

## D. 必须自研（保留 —— 原版无对应物，或技术上不可用）

| 子系统 | 为何不能复用 |
|---|---|
| **地形本体** `ContinentField` / `CellGenerator` / `TerrainCharacterField` / `TypeNoiseProvider` / `HeightCurve` / `SeaBedDetail` | 这是模组存在的意义 |
| **地质系统** `StratumField`（地层）/ `TectonicField` + `TectonicDeformation`（构造）/ `LandFeatures` + `VolcanicShape`（火山） | 原版**无**地层/构造/火山概念 |

## E. 未决事项（需决策）

### E-1 金属矿：是否改为自研独占？—— ✅ **已解决（改为提供开关）**

> **处置（2026-09-16，用户提议）**：不在"维持/独占/弃自研"里三选一，而是
> **给自研加总开关** —— 想用纯原版矿的玩家可一键关闭。这与 `CaveConfig` 既有的
> "档位/开关"哲学一致，也**避免了重标定矿量的平衡风险**（默认值 = 现状）。
>
> - 新增 `[Ores] oreVeinsEnabled`（默认 `true`）；`false` = 关闭自研地质矿脉 ⇒ 只剩原版矿；
> - **语义差异必须记住**：矿**有**原版替身（`ore_*` 始终生成）⇒ OFF = "纯原版矿"；
>   而洞穴**没有**替身 ⇒ OFF = "地下无洞穴"；
> - 门控在 `OreVeins.beginColumn`（唯一入口 + 在缓存之前，防脏读）；
> - 门禁：`OreVeinProbe` **判据8**「关闭 ⇒ 零产出」，实测带内列=0 / 命中=0 PASS。
>
> 以下为决策时的原始分析（保留）：



现状：**原版金属矿打底 + 自研 `OreVeins` 叠加（约原版的 1/10）**。

| 方案 | 做法 | 代价 |
|---|---|---|
| 维持现状 | 两者并存 | "按岩性成矿"信号仅占 ~10% ⇒ **几乎不可见**；语义不纯 |
| 自研独占 | 在 `VanillaDecorationFilter` 里再把 8 种金属矿加入剔除集 | 矿量掉到 ~1/10 ⇒ **世界明显缺矿**，必须重新标定 `PROSPECT_T`（改玩法手感，需实机校准） |
| 弃自研 | 删 `OreVeins` | 失去唯一的"地质成矿"差异化；少 ~500 行 |

> **本会话未擅自改动**：三个方案都会改变玩家已验证过的矿量手感，属**平衡决策**。
> 注：自研矿脉用的是**原版方块**（`COAL_ORE` 等）⇒ 与"不新建方块/物品"约束不冲突。

### E-2 雪 / 冰：两套规则并存（已论证为互补）

- **我们的**：`cell.isSnow`（海拔/纬度/湿度）⇒ `surfaceY+1` 铺 1 层雪。**海拔雪线是本模组特色**。
- **原版的**：`freeze_top_layer`（每群系每 chunk，最后一步）⇒ 按**群系温度**铺雪 / 水面结冰。
- **结论**：两者是**并集**，方向一致（冷处更冷），不产生矛盾：
  - 冷群系低海拔 → 原版铺雪（合理）
  - 暖群系高海拔 → 我们铺雪（这正是雪线）
  - 冷水体 → 原版结冰（期望行为）
- 若日后想让"我们的雪线"独占，一行即可：把 `freeze_top_layer` 加入 `VanillaDecorationFilter` 的剔除集。

## G. 复用机制速查（供后人照做）

**一、要"减"**（剔除原版某特征）：`VanillaDecorationFilter`
- 构造器注入过滤版 `generationSettingsGetter`，原版管线自动跳过 ⇒ **无需重写装饰循环**
- ⚠ 1.20.1 的 `BiomeGenerationSettings` **构造器不是 public** ⇒ 必须走 `PlainBuilder` 子类访问 `protected features`，以保留含空步的完整 11 步结构

**二、要"加"**（把原版某特征引入本群系）：同一注入点即可
- 例：把 `minecraft:amethyst_geode` 加回某一步 ⇒ 复用原版形状/裂纹/晶芽
- ⚠ 注意原版特征会用 `RuleTest` / 替换目标去改本地岩层（这正是 §A 岩块团块问题的成因）

**三、要"接"**（原版空实现处）：委托原版同名 API
- 例：`spawnOriginalMobs` → `NaturalSpawner.spawnMobsForChunkGeneration`
- 反例：`applyCarvers` **接不了**（无 `NoiseChunk`）
