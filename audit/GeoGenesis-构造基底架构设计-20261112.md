# 构造基底架构设计（2026-11-12）

> **本文只做架构设计，不含实现，也不含具体数值。**
>
> 目的：把「构造决定整体地形」这一层讲清楚——构造产出什么、高度怎么导出、
> 类型在哪一步介入。数值（海深、跨度等）在架构定案后再单独讨论。
>
> 前置事实见 [`GeoGenesis-模组结构核查-20261112.md`](GeoGenesis-模组结构核查-20261112.md)。

---

## 〇、先说清此前的错误方向（避免重犯）

本轮曾试过：在既有噪声高度上，为深海贴一条「按离脊距离变化」的深度曲线
（已回退，生产代码恢复原状）。

**它为什么不是「构造决定地形」**：

| 项 | 那条曲线做的事 | 「构造决定地形」应有的做法 |
|---|---|---|
| 介入点 | 只改 `deepBlocksRaw` 这一个局部函数的返回值 | 改**高度基准**的产出来源 |
| 构造的作用 | 在噪声结果上叠加一个 `dist` 项 | 由构造**导出**高度，噪声只做局部细节 |
| 海洋 | 只有深海段被覆盖，浅海/岸段完全不受影响 | 海陆一体：基准覆盖全部 |
| 陆地 | **完全没有触及** | 同样由构造导出 |

⇒ 那条曲线只是在噪声上打补丁。**它解决的从来不是「构造决定地形」这个问题。**

---

## 一、目标与判据

**目标**：地形高度的**基准**（macro 尺度）由构造决定；类型负责局部形态。

**可判据的成功标准**（架构层面，不是数值）：

1. 高度基准不来自"某个噪声映射到某个区间"，而来自**可解释的物理量**
2. 换世界种子时，**大尺度地貌格局**（哪里是洋盆、哪里是陆核、哪里是造山带）
   随构造格局改变，而不是随噪声相位改变
3. 类型在基准之上做局部形态，**不再自己产生基准级落差**
4. 海陆过渡（海岸）沿用既有 `edge` 剖面机制，不因换基准而断裂

## 二、构造层产出什么（物理量，不是高度）

### 2.0 现有可用输入

`TectonicField.Sample` 已经提供（`TectonicField.java:409-448`）：

| 字段 | 含义 | 值域 | 连续性 |
|---|---|---|---|
| `dist` | 到最近板块边界距离 | ≥0（内部为大值） | 连续，但在 Voronoi 边界切换处有顶点折痕 |
| `stress` | 连续应力 | [−1,1] | ✅ 连续（`dot/|(dot,cross)|` 推导） |
| `rate` | 相对速度（活动强度） | ≈0~2 | ⚠ **离散标签**，不得参与地形合成 |
| `btype` | 边界类型枚举 | 4 值 | ❌ 离散，边界处跳变 |
| `tangentX/Z` | 边界切向 | 单位向量 | 顶点处微小不连续 |
| `alongCoord` | 沿走向连续代理 | — | ✅ 连续（`(d1+d2)/2`，刻意设计） |

另有 `TectonicField.shellFromC(c)`（`:814`）：由连续 c 场派生的**壳属性**（0=洋壳 1=陆壳）。

**关键**：`btype`/`rate` 是离散标签，项目铁律明确禁止它们参与地形合成
（`TectonicField.java:695-700`）。可用的是 `dist` / `stress` / `shellS` / `alongCoord`。

### 2.1 建议的物理量集合

构造层应该产出**物理属性**，高度是它们的**导出量**：

| 物理量 | 符号 | 来源 | 说明 |
|---|---|---|---|
| 壳类型 | `shellS` ∈ [0,1] | `shellFromC(c)` | 0=洋壳（薄/dense）1=陆壳（厚/轻） |
| 岩石圈厚度 | `thickness` | 由 `dist` + `shellS` 导出 | 洋壳薄、陆壳厚；远离扩张中心增厚 |
| 岩石圈密度 | `density` | 由 `shellS` 导出 | 洋壳密度大、陆壳小 |
| 构造活动度 | `activity` | `smoothPos(|stress|)` | 汇聚/离散强则活动度高 |

**这些量的共同特点**：都是**连续**的、**有物理意义**的、**不直接等于高度**。

### 2.2 为什么必须"导出"而不是"直接给高度"

直接给高度偏置（`elevationOffset` 的做法）已经被实测否决
（`TectonicField.java:620-634`）：

1. 与权重调制重复 ⇒ 双重加深
2. **连锁增强地形雨**：`PrecipField.orographicGain` 基于高度差，直接抬 `e`
   会推高全局降水、稀释干旱区区分度（实测最干桶 0.922→0.959）

**导出量的优势**：物理量本身不参与气候，只有最终高度参与。
且同样的厚度/密度在陆海两侧的换算可以分开处理（陆 236 格/e、海 127 格/e）。

## 三、物理量 → 高度基准的导出

### 3.1 导出公式（架构层面，不给数值）

采用参考项目 `SimpleTectonics` 的浮力思路（`Litho::buoyancy`，MIT）：

```
height ∝ thickness × (1 − density)
```

含义：**厚而轻 ⇒ 高；薄而重 ⇒ 低**。这不是拟合出来的经验式，而是
岩石圈均衡（isostasy）的一阶近似。

**为什么用它**：
- 它把"高度"变成厚度的**导出量**，而非独立参数
- 构造只要给出厚度与密度，高度自动合理
- 洋壳（薄+重）自然落在深海平原，陆核（厚+轻）自然高出

**局限**（必须写在实现里，不能假装没有）：
- 真实均衡还要考虑地幔密度、弹性厚度等，这里是**一阶简化**
- 简化到什么程度可接受，需要出图对比后才能定

### 3.2 海陆必须用同一套导出，不能分家

这是本设计最重要的一条。

**理由**：海岸线由"高度穿越海平面"涌现（用户铁律）。若陆侧用一套高度来源、
海侧用另一套，**岸线处必然出现两套来源对不上**——表现为台阶或错位。

**正确形式**：

```
eBase(x,z) = f(thickness(x,z), density(x,z))      ← 一个函数，全图适用
e(x,z)     = eBase(x,z) + Δtype(x,z)              ← 类型只做局部形态
```

`shellS` 决定"该点偏向洋壳公式还是陆壳公式"，但**插值本身是连续的**
⇒ 岸线处不会出现来源切换。

### 3.3 与既有 `edge` 剖面机制的关系

现有 `MorphOceanAssembler` 用 `edge = (c+1)/2` 做三段剖面（深海→浅海→岸段）。
`edge` 来自 `ContinentField`，与 `shellS` **同源**（`shellFromC` 就是由 c 派生的）。

**架构上的处理**：
- `eBase` 负责**大尺度基准**（洋盆多深、陆核多高）
- 既有三段剖面机制**保留**，但它的 `deep` 输入改从 `eBase` 取，而非从 Perlin 取
- 这样海岸过渡行为（`shoreWidth`、`cliffFactor`、`oceanDetail`）**逐位沿用**，
  风险最小

## 四、类型在哪一步介入

依据用户裁定（海洋海岸需求基线 §一）：

> 分布只管分布，地形高度由各自类型的高度决定。

**分层**：

| 层 | 职责 | 输入 | 输出 |
|---|---|---|---|
| **① 构造基准** | 大尺度高度基底 | 种子 + 坐标 → 物理量 | `eBase`（连续，覆盖全图） |
| **② 类型分布** | 选类型 + 空间权重 | `eBase` / c / 气候 | 类型权重（连续混合） |
| **③ 类型形态** | 各类型自身的地形特征 | 类型 + 局部噪声 | `Δtype`（相对基准的增减） |
| **④ 侵蚀** | 水力侵蚀 | `eBase + Δtype` | 侵蚀后高度 |

**关键约束**：
- ③ 的 `Δtype` 必须是**局部量级**（±几格到几十格），不能改变基准级落差
- ③ 不能反向修改 ①（否则高度来源不唯一）
- ④ 作用在合成后的整体地形，不按噪声层分别侵蚀

## 五、必须解决的风险（架构级，不解决就不能落地）

| # | 风险 | 后果 | 缓解方向 |
|---|---|---|---|
| **R1** | **地形雨连锁** | 陆侧基准高度变化 → 抬升改变 → 降水分布改变 → 干旱区变形 | 分步接线：陆侧系数从 0 开始，逐档放开并测气候分类 |
| **R2** | **既有基准全失效** | `P1CellRenderProbe` 的 1401² SHA、已认可大图全部作废 | 接受；重立基准，但须保留旧值作对照 |
| **R3** | **两份 `BaseWorldSampler`** | 只改一份 ⇒ 侵蚀看到的地形 ≠ 最终地形 | 改动必须同时覆盖 `CellGenerator:244` 与 `ProcessContext:72` |
| **R4** | **类型判据不同源** | 海侧按 `e` 阈值、陆侧按 Voronoi 权重 ⇒ 岸线处类型断裂 | 统一高度后，类型判据也须统一；否则高度连续但类型断裂 |
| **R5** | **`dist` 的使用边界** | 铁律：`dist` 只能用于衰减，**绝不能作噪声坐标**（会产生绕板同心环） | 导出高度时只用 `dist` 作**单调映射**（如厚度随距离饱和增长），不做非单调变换 |
| **R6** | **性能** | 构造采样约 2130 ns/点（已优化到 1346），若每点多次采样会显著变慢 | 先测一次真实生产成本，再决定缓存；不预设收益 |
| **R7** | **海侧量程与配置脱钩** | `BLOCKS_PER_E_SEA=127` 是字面量，改 `seaLevel`/`minY` 会脱钩 | 导出高度时用 `HeightCurve` 派生量，不用字面量 |

## 六、实施顺序（每步可独立验收）

### S1 · 构造物理量层
- 新增：由 `dist` / `shellS` / `stress` 计算 `thickness` / `density` / `activity`
- **不改任何现有高度**
- 验收：物理量空间分布图（连续、无折痕；`|∇|` 长尾比在平滑范围内）

### S2 · 导出 `eBase`，但陆侧权重=0
- `eBase = f(thickness, density)`，陆侧用权重 0 压到旧值
- 海洋侧走新基准，陆地保持原样
- 验收：**产出可严格对拍**——陆侧逐位不变，海侧出对照图看形态

### S3 · 逐档放开陆侧权重
- 每档交付：生产路径全窗图 + 同窗口 A/B + 气候分类变化
- **每档必须停等你确认**（这一步会改变已认可地形）
- 验收：地形雨影响可量化、可回退

### S4 · 类型判据统一
- 高度统一后，海陆类型判据须同步（否则岸线类型断裂）
- 验收：岸线剖面图上类型与高度一致

### S5 · 全链重建基准
- 重跑 1401²、实机目检、门禁
- 旧基准保留作历史对照，不删

## 七、明确的"不做"

| 项 | 理由 |
|---|---|
| 在既有噪声高度上贴"按 dist 变化的曲线" | 那是打补丁，不是构造决定地形（本轮已否证并回退） |
| 用 `btype` / `rate` 参与地形合成 | 离散标签，边界跳变 ⇒ 线状疤痕（项目铁律） |
| 用 `dist` 作噪声坐标 | 等值线平行 Voronoi 边界 ⇒ 绕板同心环（项目铁律） |
| 用"最近邻配对"定义场 | 分片常数 ⇒ 笔直长线段 + Y 形交汇（项目铁律） |
| 直接给高程偏置（`elevationOffset`） | 已实测否决：双重加深 + 连锁地形雨 |
| 照搬 SimpleTectonics 的 GPU 质点模拟 | 与逐点解析场互斥，且有五处确定性缺口 |

## 八、架构决策（已确认 2026-11-12）

| # | 问题 | 结论 |
|---|---|---|
| **A1** | 导出公式 | ✅ **采用均衡一阶近似** `height ∝ thickness×(1−density)`（参考 SimpleTectonics `Litho::buoyancy`，MIT） |
| **A2** | 陆侧要不要一起改 | ✅ **海陆同改**。用户原话：「肯定要啊，我让你设计构造地形就是为了解决这个的，毕竟我只是之前失败才暂时保留噪声海陆海岸线。」 |
| **A3** | 既有三段海岸剖面 | ✅ **保留**，只把 `deep` 的来源从 Perlin 换成 `eBase` |
| **A4** | 类型判据 | ✅ **与高度同步统一**（S4），否则高度连续但类型断裂 |

### A2 的关键含义（必须写进实现纪律）

「**噪声海陆海岸线是失败后的临时保留，不是设计目标**。」

⇒ 这意味着：
- `edge = (c+1)/2` 三段剖面虽然当前被认可，但它的**海陆划分依据是噪声 c 场**，
  属临时状态。
- 构造基底建立后，`edge` 应由**构造导出的壳属性 `shellS`** 驱动，而不是由噪声 c 驱动。
- 但 **A3 说保留剖面结构** —— 两者不矛盾：保留的是**剖面形状机制**
  （`shoreWidth` 随高度增长、`cliffFactor` 沙/崖、`oceanDetail`），
  换掉的是**它的驱动量**（`edge` ← `shellS`）。

> 实施时：S2 先只换高度基准、`edge` 暂不动（保证可对拍）；
> `edge` 换源放到 S4，与类型判据统一一起做。

## 九、一句话总结

**构造产出物理量（厚度/密度）→ 导出统一的高度基准 → 类型在基准上做局部形态。**

数值（洋盆多深、陆核多高）是**导出结果**，不是输入参数——这是本设计与
此前"给深海贴曲线"最根本的区别。

> ⚠ 本文不含实现，也未改任何代码。等架构确认后再谈数值与落地。
